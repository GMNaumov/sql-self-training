# Мониторинг и базовые показатели

Мониторинг показывает состояние сейчас; базовая линия (baseline) описывает нормальное состояние в сопоставимом интервале. Утро распродажи и ночной простой нельзя сравнивать по одному абсолютному числу CPU.

**Пример.** Загрузка CPU выросла с 20% до 70%, но число заказов выросло в пять раз, а задержка не изменилась. Это может быть нормальное использование ресурса. CPU 30% при зависших пользователях может означать ожидание блокировки, а не наличие большого запаса производительности.

Собирайте нагрузку и результат вместе: запросы в секунду, пользовательскую длительность, ошибки, CPU, память, логические чтения, дисковые задержки, свободное место, блокировки и успешность заданий. Нужны отметки времени и сведения о рестартах.

DMV дают текущие или накопленные сведения, Extended Events — конкретные события, системные журналы — ошибки и жизненный цикл служб, Performance Monitor — временные ряды счётчиков. Эти источники дополняют друг друга.

**Контроль:** для каждого оповещения задайте причину, ответственного и первый диагностический шаг. «Метрика отклонилась» полезно только вместе с пониманием, какой сервис пострадал и что проверять. В SQL Server 2014 нет Query Store, поэтому длительную историю запросов готовят отдельно.
