# Динамические административные представления (DMV) и текущая активность

DMV (dynamic management views) — представления состояния движка. `sys.dm_exec_sessions` описывает сеансы, `sys.dm_exec_requests` — выполняющиеся запросы, `sys.dm_exec_query_stats` — накопленные показатели запросов из кеша. Это разные уровни наблюдения.

```sql
SELECT r.session_id, r.status, r.command,
       r.blocking_session_id, r.wait_type,
       r.cpu_time, r.logical_reads, t.text
FROM sys.dm_exec_requests AS r
CROSS APPLY sys.dm_exec_sql_text(r.sql_handle) AS t
WHERE r.session_id <> @@SPID;
```

Запрос исключает собственный сеанс и показывает активную работу. Текст может содержать весь пакет, а не только текущую команду; для точной команды используют смещения statement start/end. Общий обзор требует `VIEW SERVER STATE` на 2014.

**Пример.** Запрос ждёт, `blocking_session_id` указывает на 58, но 58 нет в `dm_exec_requests`. Посмотрите `dm_exec_sessions` и активные транзакции: блокировщик может быть спящим с незавершённой транзакцией.

DMV изменяются прямо во время чтения, а накопленные показатели могут сбрасываться при рестарте, вытеснении или сбросе. Снимок не является транзакционно согласованной летописью всего сервера.

**Ошибка:** считать высокий `cpu_time` в DMV временем последнего запуска без проверки значения столбца и уровня. У запроса, сеанса и записи кеша разные интервалы и единицы. Сначала прочитайте смысл метрики, затем сравнивайте.
