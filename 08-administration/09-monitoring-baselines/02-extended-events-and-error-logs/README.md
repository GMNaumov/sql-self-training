# Расширенные события (Extended Events) и журналы ошибок

Extended Events (расширенные события, XE) собирают события работы SQL Server с фильтрами и выбранными полями. Сессия XE задаёт события, действия для контекста и цель записи, например event file. Слишком широкий сбор текста и планов создаёт лишний объём и нагрузку.

**Пример расследования.** Пользователь иногда получает 1205. Сначала прочитайте `xml_deadlock_report` стандартной `system_health`, если запись сохранилась. Граф покажет запросы и ресурсы. Если данных мало, спроектируйте отдельную ограниченную сессию с фильтром и достаточным сроком хранения.

В SSMS: Management → Extended Events → Sessions. Для будущей лаборатории изучите существующую `system_health`, её цели и файлы; не меняйте стандартную сессию без причины. Для чтения и управления нужны соответствующие серверные права.

SQL Server Error Log содержит сообщения запуска, восстановления, ошибок ввода-вывода и другие записи. Это не журнал транзакций `.ldf`. История задания Agent — ещё один самостоятельный источник.

**Порядок:** зафиксируйте время инцидента и часовой пояс, найдите связанные события, сохраните контекст запроса и параметры без ненужных секретов, сопоставьте с блокировками и ресурсами. Событие ошибки без причины в приложении может быть следствием более раннего сбоя.

**Ошибка:** постоянно собирать все события всех баз «чтобы ничего не пропустить». Выберите гипотезу, фильтры, ограничение размера и срок хранения. Файлы и ring buffer имеют ограниченную ёмкость, поэтому отсутствие старой записи ничего не доказывает.
