# Счётчики производительности и базовые показатели

Счётчики производительности показывают изменение состояния во времени. Performance Monitor Windows собирает CPU, диски и объекты SQL Server. Имена объектов могут различаться для именованных экземпляров, поэтому сначала выберите нужный процесс и экземпляр.

**Пример набора:** Processor usage, Available MBytes, дисковые Avg. Disk sec/Read и Write, SQL Server Batch Requests/sec, SQL Compilations/sec, Memory Grants Pending, Page Life Expectancy. Один счётчик не объясняет всю причину. Фиксированный универсальный порог Page Life Expectancy «300 секунд» не учитывает объём памяти и нагрузку.

Снимайте с подходящим интервалом, например каждые 15 секунд в диагностическом окне, и сохраняйте бизнес-нагрузку. Слишком редкая выборка прячет пики, слишком частая увеличивает объём. Для длительного наблюдения выбирают баланс и агрегаты.

Некоторые DMV-счётчики показывают накопленное значение, а не готовую скорость. Например, для счётчика событий разность значений делят на длительность интервала, учитывая тип `cntr_type`. Не подписывайте абсолютное накопление как «в секунду».

**Сценарий.** Ночью выросли дисковые задержки и длительность отчёта одновременно с rebuild. Сопоставьте расписание и объём I/O, затем перенесите или ограничьте обслуживание в лабораторном эксперименте. Сам рост CPU не объясняет такой случай.

**Самопроверка.** Можно ли сравнивать рабочий понедельник с пустым воскресеньем как одинаковые условия? Нет: baseline должен соответствовать часу, типу нагрузки и изменениям конфигурации.
