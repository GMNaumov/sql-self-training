# Проверка целостности с DBCC

`DBCC CHECKDB` проверяет структурную и логическую согласованность объектов базы на уровне правил движка: размещение, связи страниц, индексы и другие структуры. Это не проверка правильности бизнес-формулы и не замена backup.

```sql
DBCC CHECKDB (N'AdventureWorks2014') WITH NO_INFOMSGS;
```

Команда требует ресурсов и соответствующих прав. Для большой базы планируют окно или проверку восстановленной копии, учитывая, что проверка копии не полностью заменяет контроль текущей среды хранения. `PHYSICAL_ONLY` сокращает объём проверок; это не эквивалент полного CHECKDB.

**Сценарий ошибки.** При сообщении о повреждении сохраните полный вывод, проверьте журналы и подсистему ввода-вывода, определите здоровую цепочку копий. Предпочтительный путь — восстановление из проверенных резервных копий с анализом причины. Дополнительная запись в повреждённую среду может усложнить ситуацию.

`REPAIR_ALLOW_DATA_LOSS` действительно может удалить данные ради структурной согласованности. Это крайний вариант с отдельным планом потерь и последующей проверкой ограничений и бизнеса, а не штатная команда ремонта «на всякий случай».

**Упражнение.** CHECKDB завершился без ошибок, но у всех заказов неверно начислена скидка. Противоречит ли это результату? Нет: база может быть структурно целой и хранить бизнес-ошибку. Нужны контрольные расчёты и восстановление верного состояния данных.

В текущем проекте CHECKDB не выполнялся: нет экземпляра SQL Server.
