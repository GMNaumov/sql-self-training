# Порядок восстановления и восстановление на момент времени

`NORECOVERY` оставляет базу готовой к следующим restore; `RECOVERY` завершает восстановление и открывает её. После завершения нельзя просто продолжить накатывать следующие журналы той же последовательности — обычно придётся начать восстановление заново.

**Учебная последовательность:** восстановите full в новую базу `AW_RestoreLab` с `MOVE` для каждого логического файла в отдельные физические пути и `NORECOVERY`; примените подходящий diff, если он используется, тоже с `NORECOVERY`; затем журналы по LSN. Логические имена возьмите из `FILELISTONLY`, не угадывайте.

Имена `LogicalDataName` и `LogicalLogName` ниже — **обязательные к замене** значения из `FILELISTONLY`. Если файлов больше двух, нужен отдельный `MOVE` для каждого. База и целевые файлы должны быть новыми учебными объектами, а не существующими данными:

```sql
RESTORE DATABASE AW_RestoreLab
FROM DISK = N'E:\SqlLabBackups\AW_full_01.bak'
WITH MOVE N'LogicalDataName' TO N'E:\SqlLabData\AW_RestoreLab.mdf',
     MOVE N'LogicalLogName' TO N'E:\SqlLabData\AW_RestoreLab_log.ldf',
     NORECOVERY;
-- Только совместимая с этой full копия:
RESTORE DATABASE AW_RestoreLab
FROM DISK = N'E:\SqlLabBackups\AW_diff_01.bak'
WITH NORECOVERY;
-- Здесь применяются все требуемые предыдущие журналы по LSN.
-- Затем журнал, содержащий выбранную цель:
RESTORE LOG AW_RestoreLab
FROM DISK = N'E:\SqlLabBackups\AW_log_003.trn'
WITH STOPAT = '2014-01-15T10:20:00', NORECOVERY;
RESTORE DATABASE AW_RestoreLab WITH RECOVERY;
```

Дата условна: она должна попадать в реальную цепочку лабораторных копий. В восстановлении на время используйте согласованную цель `STOPAT` для применяемых log backup, как требует выбранный сценарий. Не подставляйте эту дату в исходную копию и не ожидайте готового результата.

**Пример бизнеса.** Ошибочное удаление произошло в 10:21. Цель — состояние непосредственно до него, а не автоматически 10:20 из учебника. Уточните часы, временную зону и точную операцию, сохраните текущую базу и восстанавливайте отдельно для проверки.

**Ошибки:** перепутать физический и логический путь; применить diff от другой full; открыть базу слишком рано; применять `REPLACE` без анализа риска перезаписи.
