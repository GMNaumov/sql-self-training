# Полные и разностные резервные копии

Полная копия (full backup) содержит данные и достаточно журнала для согласованного восстановления. Разностная (differential) содержит изменённые экстенты с момента своей дифференциальной базы — обычно последней обычной полной копии. Это не изменения со времени предыдущей разностной.

В будущей лаборатории, при существующей папке и правах службы:

```sql
BACKUP DATABASE AdventureWorks2014
TO DISK = N'E:\SqlLabBackups\AW_full_01.bak'
WITH CHECKSUM, COMPRESSION;
BACKUP DATABASE AdventureWorks2014
TO DISK = N'E:\SqlLabBackups\AW_diff_01.bak'
WITH DIFFERENTIAL, CHECKSUM, COMPRESSION;
```

Выходные пути намеренно отличаются от исходных `.bak` проекта. Создавайте отдельные имена: без `INIT` файл backup может дополняться новыми наборами, что требует выбора позиции `FILE` при restore.

**Пример цепочки.** Воскресенье full F1, понедельник diff D1, вторник diff D2. Для вторника нужны F1 и D2; D1 не нужен. Если в понедельник выполнить обычный full F2, последующие diff будут связаны с F2. Для внеплановой полной копии, не меняющей дифференциальную базу, используют `COPY_ONLY`.

Полный backup в модели FULL не заменяет резервирование журнала и сам по себе не усекает его. Сжатие требует CPU и проверяется по времени и объёму. Checksum помогает обнаруживать некоторые повреждения, но не доказывает логическую корректность всей базы.

**Самопроверка.** Нужно ли восстанавливать все дневные differential подряд? Нет, достаточно выбранной подходящей последней разностной к своей полной базе.
