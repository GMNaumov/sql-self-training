# Резервное копирование и восстановление

Резервная копия создаёт возможность вернуть данные к определённому состоянию. Восстановление собирает это состояние из допустимой последовательности копий и журнала. Копия, которую никто не пробовал восстанавливать, остаётся неподтверждённым элементом стратегии.

**Пример:** полная копия ночью, разностная днём, журнал каждые 15 минут. При сбое вечером выбирают совместимую полную базу, подходящую разностную и все требуемые копии журнала до цели. Последняя по дате разностная подходит не к любой полной.

Начните с требований RPO и RTO, затем разберите типы копий, цепочку LSN и порядок restore. Раздельно учитывайте файлы, сертификаты, системные базы, задания, логины и параметры приложения. Копирование одной пользовательской базы не переносит весь экземпляр.

**Критерий готовности:** восстановить на отдельный экземпляр, проверить целостность и важные бизнес-запросы, измерить время, документировать последовательность. `VERIFYONLY` полезен, но не заменяет эту проверку. Все команды ниже предназначены для будущей лаборатории и не исполнялись.
