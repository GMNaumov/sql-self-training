# Резервное копирование системных баз и сертификатов

Пользовательская база — часть экземпляра. `master` хранит важные серверные метаданные, `msdb` — задания Agent и историю, `model` служит шаблоном создания баз. `tempdb` пересоздаётся при старте и не резервируется обычным способом.

**Пример аварии.** AdventureWorks восстановлен, но приложение не входит, а ночные задания отсутствуют. Причина может быть в потерянных логинах с нужными SID, заданиях, credentials или настройках экземпляра. Backup пользовательской базы их не содержит полностью.

План должен включать копии системных баз после значимых изменений, экспорт необходимых конфигураций и документированный порядок восстановления на совместимой сборке. Восстановление `master` имеет специальный режим и может остановить экземпляр; это не обычное упражнение в рабочей системе.

Для сертификата шифрования резервной копии или TDE сохраните сертификат и его закрытый ключ. В подготовленной лаборатории схема экспорта:

```sql
-- В базе, где создан сертификат LabBackupCert:
BACKUP CERTIFICATE LabBackupCert
TO FILE = N'E:\SqlLabKeys\LabBackupCert.cer'
WITH PRIVATE KEY
(
    FILE = N'E:\SqlLabKeys\LabBackupCert.pvk',
    ENCRYPTION BY PASSWORD = 'Replace_With_Protected_Lab_Secret'
);
```

Пароль — обозначение для замены, не готовый секрет. Закрытый ключ и пароль хранят защищённо и проверяют импортом на отдельном сервере. Приведённый экспорт не создаёт сертификат автоматически.

**Ошибка:** хранить ключ только рядом с зашифрованным `.bak` и считать угрозу кражи полностью решённой. Разделяйте доступ и обеспечивайте восстановимость ключей.
