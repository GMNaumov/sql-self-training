# Стратегия резервного копирования, RPO и RTO

RPO (recovery point objective) — допустимая потеря данных по времени. RTO (recovery time objective) — допустимое время восстановления сервиса. Это бизнес-требования, из которых выводят расписание и инфраструктуру.

**Пример.** Магазин допускает потерю не более 15 минут и простой не более часа. Ночная полная копия без журнала не обеспечивает такой RPO. Журнал каждые 15 минут даёт подходящее номинальное окно только при успешных копиях, доступной цепочке и отсутствии других потерь. Мониторить нужно фактическое последнее успешное копирование, а не расписание.

RTO включает обнаружение сбоя, решение о восстановлении, получение копий и ключей, передачу файлов, restore, проверку и переподключение приложения. Сам restore за 40 минут не доказывает RTO в 60 минут, если копии ещё час скачиваются.

Храните несколько поколений копий, отдельную защищённую копию вне основного сервера и ключи отдельно с контролируемым доступом. Определите срок хранения с учётом обнаружения ошибочных изменений: повреждение отчёта могут заметить спустя неделю.

**Упражнение.** Полная копия в 00:00, журнал в 12:00, 12:15, 12:30; сбой в 12:37. Без доступного хвоста журнала последняя достижимая точка обычно ограничена 12:30, а с успешным tail-log backup может быть позже. Точную достижимость проверяют цепочкой и восстановлением.

**Ошибка:** считать RAID, реплику или снапшот единственной резервной копией. Удаление пользователем может быстро распространиться на доступные копии данных.
