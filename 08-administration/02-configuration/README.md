# Настройка экземпляра и баз данных

Настройки бывают серверные, базовые и сеансовые. Например, `max server memory` относится к экземпляру, совместимость — к базе, уровень изоляции — к подключению. Область изменения нужно понимать до выбора значения.

```sql
SELECT name, value, value_in_use, is_dynamic
FROM sys.configurations
WHERE name IN (N'max server memory (MB)', N'max degree of parallelism',
               N'cost threshold for parallelism');
SELECT name, compatibility_level, recovery_model_desc
FROM sys.databases;
```

`value` — настроенное значение, `value_in_use` — фактически действующее. Некоторые изменения требуют дополнительных действий или рестарта. Запросы здесь только читают сведения.

**Пример планирования.** На машине с SQL Server, SSAS и ОС нельзя отдать весь объём RAM движку. `max server memory` ограничивает важную часть памяти SQL Server, но не абсолютно все выделения процесса. Оставьте ресурс для ОС, других служб и пиков, затем наблюдайте.

`MAXDOP` определяет доступную степень параллелизма, порог стоимости — когда оптимизатор рассматривает параллельный вариант. Это не порог длительности в секундах. Значения выбирают с учётом CPU, NUMA и запросов, а не универсальным правилом.

**Порядок изменения:** зафиксировать исходное значение и причину, измерить базу, изменить один фактор в лаборатории, проверить разные нагрузки, подготовить возврат. Не включайте `AUTO_SHRINK`: регулярное сжатие и последующий рост создают лишнюю работу.

**Самопроверка.** Совместимость 120 разрешает `STRING_AGG` на SQL Server 2014? Нет, такой функции в движке 2014 нет.
