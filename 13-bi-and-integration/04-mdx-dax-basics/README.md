# Основы MDX и DAX

MDX работает с многомерными координатами, участниками, кортежами и наборами. DAX описывает вычисления и запросы табличной модели через таблицы и контексты. Это самостоятельные языки; их `SELECT` или агрегат нельзя механически читать как T-SQL.

Для учебного куба, который вы сами создали с именами `LabSales`, `Date` и мерой `Sales Amount`, форма MDX:

```mdx
SELECT {[Measures].[Sales Amount]} ON COLUMNS,
       [Date].[Calendar Year].[Calendar Year].Members ON ROWS
FROM [LabSales]
```

Имена условны и должны соответствовать проекту. Этот куб не содержится автоматически в AdventureWorksDW. Результат пересекает выбранную меру с каждым участником уровня года.

Для Tabular с импортированными именами таблиц:

```dax
EVALUATE
SUMMARIZE(
    FactInternetSales,
    DimDate[CalendarYear],
    "Amount", SUM(FactInternetSales[SalesAmount])
)
```

Нужна корректная связь календаря и факта. `EVALUATE` возвращает таблицу запроса; определение меры — другая конструкция. Примеры выполняются при подключении к Analysis Services, не к Database Engine.

**Проверка:** сопоставьте годовую сумму с SQL по тем же фактам. При несовпадении сначала проверьте модель, контекст и processing. Для 2014 используйте функции, существовавшие в том движке: не подставляйте `SUMMARIZECOLUMNS`, `VAR` и современные временные функции без проверки версии.

**Самопроверка.** Что возвращает MDX-ось? Набор координат аналитической модели, а не просто строки исходной SQL-таблицы.
