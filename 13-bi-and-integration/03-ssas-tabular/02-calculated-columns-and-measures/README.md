# Вычисляемые столбцы и меры DAX

Вычисляемый столбец (calculated column) вычисляет значение для строки и хранится в импортируемой модели после обработки. Мера (measure) считается в контексте текущего запроса: выбранных годов, продуктов и других фильтров.

В учебной модели с таблицами DW:

```dax
Sales Amount := SUM(FactInternetSales[SalesAmount])
Quantity := SUM(FactInternetSales[OrderQuantity])
Average Unit Sales := DIVIDE([Sales Amount], [Quantity])
```

Это определения мер, а не T-SQL для SSMS Database Engine. `DIVIDE` обрабатывает нулевой знаменатель; без альтернативного результата возвращает blank. При суммах 100 и 300 и количествах 1 и 3 общая цена единицы равна 100.

`CALCULATE` изменяет контекст фильтра. Например, `CALCULATE([Sales Amount], ALL(DimProduct))` убирает фильтр продукта, сохраняя другие подходящие фильтры. Доля текущего продукта в таком знаменателе отличается от доли во всей истории, если остаётся фильтр года.

Row context описывает текущую строку при вычислении столбца или итерации; filter context — выбранное множество. Это основное различие DAX, которое нельзя заменить представлением «формула как в ячейке Excel».

В SQL Server 2014 не используйте `VAR` и новые DAX-конструкции из более поздних движков. **Ошибка:** создать столбец с повторённой общей суммой и затем складывать его. Для динамического итога нужна мера.

**Самопроверка.** Меняется ли мера при выборе другого года? Да, если календарная связь корректна. Сохранённый вычисляемый столбец не пересчитывается отдельно под каждый щелчок фильтра.
