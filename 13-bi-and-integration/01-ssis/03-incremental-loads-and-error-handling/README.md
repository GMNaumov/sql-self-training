# Инкрементальные загрузки и обработка ошибок

Инкрементальная загрузка переносит изменения после последнего согласованного состояния. Контрольная отметка (watermark) должна обновляться только после успешной публикации. Иначе пакет может объявить обработанными строки, которые не дошли до факта.

**Пример.** Последняя отметка — `ModifiedDate=T` и ключ 500. Извлекайте строки позже T либо с той же T и большим ключом, если источник гарантирует такой порядок. Верхнюю границу зафиксируйте на начало извлечения. Для изменений задним числом понадобится иной механизм или окно повторной обработки.

В staging храните `BatchID`, ключ источника и контрольные суммы/атрибуты. Перед вставкой факта проверяйте устойчивый ключ «заказ+позиция». Повтор одного пакета должен приводить к тому же целевому состоянию. Удаления требуют отдельного сигнала: одна дата модификации живых строк не сообщает об исчезнувших.

В SQL Server 2014 Enterprise можно изучать Change Data Capture (CDC), но его включение и захват требуют настроенного сервера, Agent и отдельной политики хранения. Не считайте наличие функции автоматической готовностью источника.

**Сбой на середине.** Сохраните диагностические данные, оставьте watermark прежним, очистите или переиспользуйте staging по `BatchID`, затем повторите контролируемые этапы. Пакетные checkpoints SSIS не делают внешние действия идемпотентными.

**Ошибка:** настроить бесконечный retry для неверного формата файла. Повторяют временные отказы с ограничением; плохие данные отправляют на разбор с понятной причиной.
