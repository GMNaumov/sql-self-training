# Развёртывание проектов и выполнение пакетов в SSISDB

В project deployment model проект собирается в `.ispac` и развёртывается в каталог `SSISDB`. Environment хранит значения для среды; ссылки связывают их с параметрами проекта и пакета. Стенд разработки и продуктив должны отличаться настройками, а не ручным редактированием пакета перед каждым запуском.

**Пример.** Проект `SalesETL` содержит пакет загрузки. В среде Lab задано подключение к учебному DW и входная папка. После развёртывания сопоставьте параметры, выполните Validate, затем ручной запуск и посмотрите execution reports. Только после проверки настройте шаг Agent нужного типа и расписание.

В 2014 каталог — серверная инфраструктура, не просто папка проекта на диске. Для настройки требуются необходимые службы, права и совместимые инструменты. Сам `.ispac` не включает все внешние файлы, драйверы, права на папки и базы.

Секретные параметры помечают и хранят с надлежащим доступом. Резервируйте `SSISDB` и необходимые ключи согласно процедуре восстановления. Протоколирование выбирайте достаточно подробным для диагностики, но учитывайте объём хранения.

**Ожидаемая проверка:** запуск под реальной служебной учётной записью видит файл и обе базы; повтор не создаёт дубликатов; сбой отображается оператору; можно восстановить прежнюю версию проекта.

**Ошибка:** пакет работает из среды разработки, но не из Agent. Проверьте контекст, параметры, архитектуру драйвера, путь и права службы; не назначайте сразу административные права всем компонентам.
