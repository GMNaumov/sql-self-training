# Поток данных (Data Flow) и преобразования

Data Flow состоит из источников, преобразований и приёмников. OLE DB Source читает данные; Derived Column вычисляет поля; Data Conversion меняет тип; Lookup ищет соответствие; Conditional Split разделяет строки по условиям; OLE DB Destination загружает результат.

**Пример.** Из файла приходят `ProductCode`, дата и сумма текстом. Сначала проверьте формат и преобразуйте в согласованные `date` и `decimal`. Lookup находит `ProductKey` измерения. Строки с неизвестным кодом идут в отдельную обработку или к согласованному «неизвестному продукту», а не молча исчезают.

Тип строки SSIS и тип SQL Server не одно и то же: различайте Unicode и non-Unicode, длину, precision и scale. Обрезка значения может быть ошибкой даже при формальном успехе пакета. Направьте error output с контекстом исходной строки и кодом ошибки.

Для большого потока полезен fast load с осмысленными размерами пакета и commit. Lookup caching выбирают по объёму справочника и памяти. Sort и некоторые другие преобразования требуют накопления данных; не вставляйте сортировку без необходимости.

**Ошибка:** использовать OLE DB Command для отдельного обновления каждой из миллионов строк. Сравните загрузку staging и наборный `UPDATE`/`INSERT` на сервере. Это также упрощает проверку количества и повторный запуск.

**Самопроверка.** Где проверять, что сумма не отрицательна? В явном правиле преобразования/валидации и при необходимости ограничением целевой модели; один успешный type conversion не проверяет бизнес-диапазон.
