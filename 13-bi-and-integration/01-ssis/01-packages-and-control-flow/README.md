# Пакеты и поток управления (Control Flow)

Control Flow управляет задачами: Execute SQL Task запускает SQL, File System Task работает с файлами, Data Flow Task переносит строки, Sequence Container группирует этапы. Связи precedence constraints задают, когда следующий шаг разрешён: успех, ошибка, завершение или выражение.

**Лабораторный сценарий «файл продаж»:** проверка входа → создание записи `BatchID` → Data Flow в staging → SQL-проверка ключей → загрузка факта → отметка успеха. Ветка ошибки сохраняет причину и не отмечает пакет успешным. При отсутствии файла нужно различать штатный пропуск и ожидаемый, но не доставленный источник.

Параметр задаёт внешнюю настройку проекта или пакета; переменная хранит рабочее состояние. Например, параметр `InputFolder` получает среду, а переменная `CurrentFile` меняется в Foreach Loop Container. Типы значений и область видимости важны при выражениях.

Контейнер не делает все вложенные действия одной SQL-транзакцией автоматически. Пакетные transaction options, распределённые транзакции и подключения имеют отдельные условия. Для простого ETL часто надёжнее явно спроектировать staging и атомарную публикацию в базе.

**Ожидаемый результат:** оператор видит конкретный провалившийся этап, а данные остаются в последнем согласованном опубликованном состоянии.

**Ошибка:** соединять все задачи условием Completion, а затем всегда записывать «успешно». Completion включает ошибочное завершение; связь должна выражать реальный договор этапов.
