# Публикация отчётов, доступ и подписки

Развёртывание публикует RDL, общие источники и другие ресурсы на report server. После этого задаются роли папок, параметры источников, execution options и расписания. Сохранённые настройки сервера могут отличаться от локального проекта.

**Пример.** Руководитель открывает отчёт вручную с выбранным годом. Подписка (subscription) создаёт PDF утром без его интерактивного входа и доставляет настроенным способом. Для этого нужны пригодные credentials источника, настроенная доставка, Agent для расписаний native mode и работоспособный report server.

Data-driven subscription определяет получателей и параметры по данным; в целевой Enterprise 2014 она доступна при соблюдении условий. Это не разрешение отправлять произвольные данные любому адресу: список получателей и контекст выборки нужно контролировать.

В native mode проверьте права роли просмотра и управления, не назначайте всех Content Manager. Доступ к папке отчётов не всегда ограничивает данные источника нужным образом. Проверяйте сценарий обычного читателя и фонового запуска отдельно.

Резервируйте базы ReportServer и ключ шифрования SSRS через соответствующую процедуру. Без ключа сохранённые credentials и другие зашифрованные значения могут оказаться недоступными после переноса.

**Проверка:** опубликованный отчёт даёт верную сумму, подписка завершилась и результат доступен назначенному получателю, журнал показывает ошибку доставки при тестовом сбое. В рамках текущей задачи никакие рассылки не настраиваются и не отправляются.

**Ошибка:** считать зелёный deploy доказательством работающей подписки. Публикация, выполнение запроса, рендеринг и доставка — отдельные этапы.
