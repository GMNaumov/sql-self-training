# Источники данных, измерения и иерархии

Data Source задаёт подключение к источнику, Data Source View (DSV) — используемые таблицы и связи. Измерение состоит из атрибутов, ключей и иерархий. Отображаемое имя и ключ атрибута могут быть разными.

**Пример календаря:** ключ дня — `DateKey`, имя — полная дата; иерархия год → квартал → месяц → день. Если ключ месяца задать только номером 1–12, январь всех лет ошибочно станет одним элементом. Нужен составной ключ года и месяца либо отдельный уникальный ключ месяца.

Для продукта используйте `ProductKey` как ключ строки и `EnglishProductName` как отображение. Подкатегория и категория связываются по своим ключам. Relationships между атрибутами должны отражать настоящую зависимость, а не только желаемый порядок в интерфейсе.

При обработке проверьте уникальность ключей и поведение неизвестного участника. Ошибки duplicate key часто означают неверно выбранное зерно, а не требование «игнорировать ошибки». Исторические версии одного бизнес-кода — отдельные участники по суррогатным ключам.

**План лаборатории:** создайте только календарь, разверните и обработайте; проверьте, что месяцы разных лет не смешались. Затем добавляйте продукт. Так проще локализовать ошибку, чем сразу строить весь куб.

**Самопроверка.** Почему сортировка месяцев по имени даёт неудобный порядок? Лексический порядок не равен календарному; используйте согласованный числовой порядок и уникальный контекст года.
