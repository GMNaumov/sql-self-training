# Кубы, меры и связи измерений

Группа мер (measure group) представляет фактовый источник на определённом зерне. Мера задаёт агрегируемую величину. Связи измерений с группой мер определяют, как фильтры ограничивают события. Неправильная связь даёт убедительные, но неверные суммы.

**Пример.** `FactInternetSales` связывается с датой через `OrderDateKey`, продуктом через `ProductKey`, клиентом через `CustomerKey`. Можно добавить role-playing измерения даты отправки и срока. Для каждого укажите правильный внешний ключ, а не копируйте связь даты заказа.

`SUM(SalesAmount)` — аддитивная сумма при согласованном определении. Средняя цена требует `SalesAmount / Quantity` в текущем контексте, а не суммирования цен или усреднения средних. Уникальные покупатели требуют distinct count с подходящей моделью, а не обычного count фактов.

В SSDT вкладка Dimension Usage показывает связи и гранулярность. Проверьте детальный день, месяц и общий итог SQL-запросами. Если измерение не связано с measure group, значения могут повторяться в каждом его элементе, что не означает реального распределения продаж.

**Упражнение.** Продажи 100 и 300 при количествах 1 и 3 дают общую цену единицы 100. Если группы имеют разные размеры, усреднение групповых цен без весов может дать другой результат.

**Ошибка:** добавлять меру «остаток» с обычным SUM по времени. Для снимков нужен согласованный полуаддитивный расчёт, например последнее состояние периода, с явным бизнес-правилом.
