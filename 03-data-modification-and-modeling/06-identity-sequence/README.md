# IDENTITY и последовательности

`IDENTITY` выдаёт числовые значения при вставке в конкретную таблицу. Последовательность (sequence) — отдельный объект базы; значение можно запросить до вставки и использовать в разных таблицах. Оба механизма допускают пропуски.

```sql
CREATE TABLE #Ticket
(
    TicketID int IDENTITY(1,1) PRIMARY KEY,
    Caption nvarchar(100) NOT NULL
);
INSERT INTO #Ticket (Caption)
OUTPUT inserted.TicketID
VALUES (N'Заказ принят');
SELECT SCOPE_IDENTITY() AS LastIdentityInScope;
```

Первая вставка в свежую таблицу выдаёт 1. `SCOPE_IDENTITY()` относится к текущей области выполнения и возвращает `numeric(38,0)`. `@@IDENTITY` может захватить значение, созданное триггером, а `MAX(ID)` подвержен гонке с другими сеансами. Для нескольких строк удобнее `OUTPUT`.

Для отдельной постоянной учебной базы синтаксис последовательности: `CREATE SEQUENCE dbo.OrderNumber AS bigint START WITH 1000 INCREMENT BY 1;`, затем `SELECT NEXT VALUE FOR dbo.OrderNumber;`. Создание объекта и выдача номера — самостоятельные действия; здесь они только описаны.

Откат транзакции не возвращает уже выданный identity или sequence. Кеширование, ошибки и рестарты также могут давать разрывы. `IDENTITY` само по себе не заменяет `PRIMARY KEY` или `UNIQUE`: уникальность закрепляют ограничением.

**Самопроверка.** Подходит ли identity для юридического требования строго непрерывных номеров документов? Само по себе нет. Нужен отдельный процесс нумерации с анализом отмен, конкурентного доступа и аудита, а не обещание отсутствия разрывов.
