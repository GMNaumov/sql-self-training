# Обновление и удаление данных

`UPDATE` меняет значения выбранных строк, `DELETE` удаляет сами строки. Отсутствие `WHERE` означает весь набор таблицы. Сначала определите ожидаемое количество и ключи, затем выполняйте изменение в учебной среде.

```sql
CREATE TABLE #Cart (ProductID int PRIMARY KEY, Qty int NOT NULL);
INSERT INTO #Cart VALUES (707, 2), (708, 1);
BEGIN TRANSACTION;
UPDATE #Cart SET Qty = Qty + 1 WHERE ProductID = 707;
SELECT ProductID, Qty FROM #Cart ORDER BY ProductID;
DELETE FROM #Cart WHERE ProductID = 708;
SELECT ProductID, Qty FROM #Cart;
ROLLBACK TRANSACTION;
SELECT ProductID, Qty FROM #Cart ORDER BY ProductID;
```

Внутри транзакции товар 707 получает количество 3, затем удаляется 708. `ROLLBACK` возвращает обе строки к состоянию после вставки. Временная таблица создана до транзакции, поэтому остаётся доступна. Такой откат полезен для лаборатории, но триггеры, блокировки и затраты всё равно возникают при реальном изменении.

В прикладном коде проверяйте `@@ROWCOUNT` сразу после изменения: следующая команда может изменить его. Ожидалось одно изменение, а получилось ноль — возможны неверный ключ, удалённая строка или конфликт.

**Ловушка:** `UPDATE ... FROM` с несколькими совпадениями источника для одной целевой строки не определяет надёжный выбор значения. Сначала сделайте источник однозначным агрегацией или уникальным ключом.

`TRUNCATE TABLE` удаляет все строки особым способом, имеет ограничения по связям и сбрасывает identity; это не просто короткая запись `DELETE WHERE ...`.
