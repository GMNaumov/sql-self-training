# Взаимоблокировки

Взаимоблокировка (deadlock) — цикл ожиданий: A удерживает ресурс 1 и ждёт 2, B удерживает 2 и ждёт 1. В отличие от обычной очереди, участники не могут завершиться без вмешательства. SQL Server выбирает жертву, откатывает её транзакцию и возвращает ошибку 1205.

**Лабораторная модель:** создайте `dbo.LabAccount` с ключами 1 и 2 в общей учебной базе. В окне A начните транзакцию и обновите 1. В B начните транзакцию и обновите 2. Затем A обновляет 2 и ждёт; B обновляет 1 — появляется цикл. В пережившем сеансе обязательно завершите транзакцию. Сейчас этот опыт не выполнялся.

Для анализа нужен граф взаимоблокировки (deadlock graph): какие запросы, ключи или страницы участвовали, какие режимы удерживались и запрашивались. В SQL Server 2014 событие `xml_deadlock_report` собирается стандартной сессией Extended Events `system_health`; её данные ограничены размером и сроком хранения.

**Исправление:** обновляйте счета в одинаковом порядке ключей, уменьшайте объём транзакции и проверяйте индексы. Повторять после 1205 нужно всю логическую транзакцию, с ограниченным числом попыток и задержкой. Идемпотентность не должна допустить двойную внешнюю оплату при повторе.

**Ошибка:** повышать `DEADLOCK_PRIORITY` всем запросам. Это влияет на выбор жертвы, но не убирает цикл. Другая ошибка — повторять только последнюю команду после полного отката, теряя предыдущие шаги.
