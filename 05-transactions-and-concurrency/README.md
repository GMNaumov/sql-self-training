# Транзакции и конкурентный доступ

Транзакция объединяет изменения в логически целую операцию. Конкурентный доступ (concurrency) возникает, когда разные сеансы читают и меняют одни данные одновременно. Работавший в одиночном окне код может оказаться неверным при одновременной покупке последнего товара.

**Пример.** Остаток равен 1. Два покупателя читают 1 и оба решают оформить заказ. Отдельная проверка наличия не резервирует товар. Нужно атомарное изменение с условием остатка либо обоснованная транзакционная защита.

Раздел объясняет ACID, уровни изоляции, блокировки, взаимоблокировки и версии строк. Важно различать блокировки (locks), защищающие логическую согласованность, и кратковременные внутренние защёлки (latches), защищающие структуры в памяти.

Для будущих опытов с двумя окнами создавайте обычную таблицу в отдельной учебной базе: локальная `#temp` одного окна не видна в другом. Заранее планируйте завершение каждой транзакции. Пока сервера нет, сценарии рассматриваются как модели, а не как выполненные эксперименты.
