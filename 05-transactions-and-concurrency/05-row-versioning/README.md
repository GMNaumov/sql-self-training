# Версионность строк и оптимистический доступ

Версионность строк (row versioning) позволяет читателю видеть предыдущие подтверждённые значения, пока писатель создаёт новые. Для обычных дисковых таблиц в SQL Server 2014 версии хранятся в `tempdb`. Это уменьшает конфликты чтения с записью, но требует места и не устраняет конфликтов между писателями.

Два режима различаются границей снимка. RCSI (`READ_COMMITTED_SNAPSHOT ON`) даёт снимок на начало каждой команды `READ COMMITTED`. `SNAPSHOT`, после разрешения `ALLOW_SNAPSHOT_ISOLATION`, даёт согласованность в рамках транзакции, начиная с её первого обращения к данным.

**Пример.** Отчёт выполняет два `SELECT`: итог заказов и итог позиций. Между ними оформлен новый заказ. При RCSI каждый запрос корректен сам по себе, но они могут относиться к разным состояниям. В одной snapshot-транзакции они видят согласованный снимок. При попытке обновить строку, изменённую другим после снимка, возможна ошибка конфликта обновления 3960.

```sql
SELECT name, is_read_committed_snapshot_on,
       snapshot_isolation_state_desc
FROM sys.databases
WHERE name = N'AdventureWorks2014';
```

Запрос только читает настройки. Включение режимов — отдельное изменение поведения всей базы с оценкой подключений, нагрузки и `tempdb`.

**Ошибка:** держать snapshot-транзакцию открытой часами. Старые версии нужны ей до завершения, поэтому очистка задерживается. Контролируйте длительные транзакции и место. Версионность In-Memory OLTP устроена отдельно; не переносите автоматически её детали на дисковые таблицы.
