# ACID и управление транзакциями

ACID — четыре свойства: атомарность (atomicity), согласованность (consistency), изоляция (isolation), устойчивость (durability). Перевод денег должен списать и зачислить сумму вместе. Ограничения и правильная логика сохраняют правила; уровень изоляции определяет допустимое взаимодействие сеансов; журнал позволяет восстановить подтверждённые изменения.

```sql
CREATE TABLE #Account(AccountID int PRIMARY KEY, Balance decimal(12,2));
INSERT INTO #Account VALUES (1,1000), (2,100);
BEGIN TRANSACTION;
UPDATE #Account SET Balance = Balance - 200 WHERE AccountID = 1;
UPDATE #Account SET Balance = Balance + 200 WHERE AccountID = 2;
SELECT AccountID, Balance FROM #Account ORDER BY AccountID;
ROLLBACK TRANSACTION;
```

Внутри транзакции видны 800 и 300; после rollback — 1000 и 100. Это иллюстрация атомарности, не готовый банковский алгоритм: нужны проверки существования обоих счетов, достаточности средств, ошибок и одновременной работы. Оборачивайте реальные изменения в обработку ошибок из предыдущего раздела.

В режиме autocommit отдельная команда является транзакцией. `BEGIN TRAN` расширяет границу на несколько команд. `COMMIT` подтверждает, `ROLLBACK` отменяет; не держите транзакцию открытой во время ожидания ответа пользователя.

Вложенные `BEGIN TRAN` увеличивают `@@TRANCOUNT`, но внутренний commit не фиксирует изменения независимо. Полный rollback сбрасывает всю транзакцию.

**Самопроверка.** Гарантирует ли ACID правильный курс валют, если приложение выбрало неверный? Нет: атомарность не исправляет бизнес-алгоритм. Согласованность включает явно реализованные правила.
