# Блокировки и ожидания

Блокировка (lock) защищает ресурс на время согласования операций. Разделяемая `S` нужна для чтения при блокировочной изоляции, исключительная `X` — для изменения. Несовместимый запрос ждёт освобождения ресурса: это блокирование (blocking), которое само по себе не означает аварию.

```sql
SELECT session_id, blocking_session_id, wait_type,
       wait_time, wait_resource
FROM sys.dm_exec_requests
WHERE blocking_session_id <> 0;
```

Для обзора чужих сеансов в SQL Server 2014 обычно нужно `VIEW SERVER STATE`. Диагностика показывает ожидающий запрос и блокирующий сеанс, но блокировщик может уже не выполнять запрос: открытая транзакция в «спящем» подключении также удерживает ресурсы. Дополнительно смотрите транзакции и последнее действие подключения.

**Пример.** A обновил товар и оставил транзакцию открытой. B пытается обновить тот же товар и ждёт `LCK_M_X`. Правильный первый шаг — выяснить владельца и причину незавершённой транзакции. Немедленный `KILL` может вызвать долгий откат и должен быть обоснован эксплуатационной ситуацией.

Эскалация (lock escalation) заменяет множество мелких блокировок более крупной, обычно табличной; она не обязана происходить ровно на фиксированном числе строк. Не считайте `ROWLOCK` гарантией отсутствия эскалации.

**Что улучшать:** сокращать транзакции, использовать подходящие индексы, менять данные в стабильном порядке и не ждать сеть или пользователя внутри транзакции. `SET LOCK_TIMEOUT` ограничивает ожидание, но его ошибка требует корректного завершения транзакции и обработки в приложении.
