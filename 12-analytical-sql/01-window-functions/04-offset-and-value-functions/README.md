# Функции LAG, LEAD, FIRST_VALUE и LAST_VALUE

`LAG` берёт значение предыдущей строки, `LEAD` — следующей; смещение по умолчанию равно 1. `FIRST_VALUE` и `LAST_VALUE` берут крайнее значение в рамке. Значение «предыдущее» определяется порядком окна, а не физическим расположением строк.

```sql
SELECT SalesOrderID, CustomerID, OrderDate, SubTotal,
       LAG(SubTotal) OVER
       (PARTITION BY CustomerID ORDER BY OrderDate, SalesOrderID) AS PreviousAmount
FROM Sales.SalesOrderHeader;
```

У первого заказа покупателя предыдущего значения нет, поэтому результат `NULL`. В SQL Server 2014 `LAG` не имеет современного `IGNORE NULLS`: предыдущая строка с `NULL` остаётся предыдущей.

**Пример сравнения месяцев.** Сначала получите по одной строке суммы за месяц, затем используйте `LAG`. Если февраль отсутствует, март сравнивается с январём как предыдущей строкой. Для сравнения именно с февралем дополните календарь и определите значение отсутствующих продаж.

`LAST_VALUE(SubTotal) OVER(... ORDER BY ...)` с рамкой по умолчанию часто показывает текущую строку или последнего соседа с равным ключом, а не последний заказ покупателя. Для последнего значения всего раздела используйте `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` с определённым порядком.

**Ошибка:** подставлять ноль вместо отсутствующего предыдущего значения и затем делить на него. Темп роста `Current / NULLIF(Previous,0) - 1` не определён при нулевом знаменателе; бизнес должен решить, как это отображать.
