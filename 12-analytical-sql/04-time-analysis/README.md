# Анализ по времени

Временной анализ требует полного календаря и определения периода. Календарный и финансовый год могут различаться; неделя зависит от принятого правила; дата заказа и дата отправки описывают разные события.

```sql
SELECT d.FullDateAlternateKey AS SalesDate,
       COALESCE(SUM(f.SalesAmount), 0) AS Amount
FROM dbo.DimDate AS d
LEFT JOIN dbo.FactInternetSales AS f
  ON f.OrderDateKey = d.DateKey
WHERE d.FullDateAlternateKey >= '20140101'
  AND d.FullDateAlternateKey <  '20140201'
GROUP BY d.FullDateAlternateKey
ORDER BY d.FullDateAlternateKey;
```

Контекст — DW. Календарь слева сохраняет дни без продаж, если они есть в `DimDate`. Фильтр по факту, перенесённый в `WHERE`, мог бы удалить эти дни. Здесь отсутствие фактов трактуется как нулевая продажа; для отсутствующей загрузки это может быть неверно, поэтому сверяйте готовность ETL.

Для сравнения год к году сопоставляйте согласованные периоды. Неполный текущий месяц нельзя без пояснения сравнивать с полным прошлогодним. Високосный год и финансовая неделя требуют правила, а не произвольного `DateKey - 10000`.

`DATEADD` и настоящие типы дат безопаснее арифметики над ключами. В SQL Server 2014 нет `AT TIME ZONE`: временные зоны и исторические переходы нужно решать внешним договором или собственной проверенной моделью.

**Самопроверка.** Одинакова ли сумма по месяцу заказа и отправки? Не обязательно: один заказ может быть оформлен в конце месяца и отправлен в следующем.
