# Блоки ATOMIC и ограничения T-SQL в SQL Server 2014

`BEGIN ATOMIC` задаёт неделимую область native-процедуры. Если внешней транзакции нет, блок начинает собственную; при успешном завершении она подтверждается. Внутри уже активной транзакции используется точка сохранения. Некоторые ошибки делают непригодной всю транзакцию, поэтому обработчик должен учитывать её состояние.

В блоке фиксируют `TRANSACTION ISOLATION LEVEL` и `LANGUAGE`. Ручные `BEGIN TRAN`, `COMMIT` и `ROLLBACK` внутри native-процедуры не поддерживаются. Атомарность не гарантирует успешность: проверка конфликтов может отменить попытку.

**Пример.** Native-процедура вставляет состояние заказа, затем меняет связанный счётчик в памяти. Если возникает ошибка, нельзя оставить только вставку. Приложение должно получить ошибку и решить, допустим ли повтор всей операции.

В 2014 поддерживаемое подмножество T-SQL значительно уже обычного: нет произвольного динамического SQL, обращения к дисковым таблицам, `MERGE`, CTE и полного набора соединений; внешние соединения в native-коде этой версии не поддерживаются. Конкретную форму запроса проверяйте через Native Compilation Advisor и на целевом экземпляре. Поддержка новых конструкций в SQL Server 2016+ не доказывает их наличие здесь.

**Ошибка:** считать `ATOMIC` общей заменой `BEGIN...END` в любом T-SQL-пакете 2014. Это специальная конструкция native-процедур. Другая ошибка — повторять конфликт без ограничения и без проверки внешних побочных действий: письмо или платёж могут выполниться дважды.
