# Нативно скомпилированные хранимые процедуры

Нативно скомпилированная процедура (natively compiled stored procedure) преобразуется в машинный код для работы с In-Memory OLTP. Это уменьшает накладные расходы коротких операций, но не заменяет оптимизацию алгоритма и не делает сложный отчёт подходящей нагрузкой.

В SQL Server 2014 модуль использует `NATIVE_COMPILATION`, `SCHEMABINDING`, явно заданный контекст `EXECUTE AS` и один внешний `BEGIN ATOMIC`. Он обращается к memory-optimized таблицам; прямой доступ к обычной дисковой таблице из native-процедуры не поддерживается.

**Пример разделения.** Чтение справочника товара из `Production.Product` остаётся в обычном T-SQL. Короткое обновление отдельного состояния заказа в таблице памяти можно вынести в native-модуль. Это не означает, что разрешено произвольно разделить одну требующую атомарности операцию на независимые commit.

Прежде чем переносить код, проверьте поддерживаемые команды, функции, соединения, транзакции и параметры именно для 2014. Обычная процедура может работать с memory-optimized таблицей без native-компиляции, что позволяет оценить эффект хранения отдельно от эффекта компиляции.

**Контроль:** подтвердите выигрыш по CPU, длительности, пропускной способности и проценту конфликтов на той же нагрузке. Не используйте рекламное ускорение как измерение проекта. Источник: [native-процедуры в SQL Server 2014](https://www.microsoft.com/en-us/sql-server/blog/2014/02/21/using-natively-compiled-stored-procedures-in-sql-server-2014/).
