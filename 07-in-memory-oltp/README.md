# In-Memory OLTP

In-Memory OLTP — отдельный механизм обработки таблиц, оптимизированных для памяти (memory-optimized tables). Он появился в SQL Server 2014. Это не просто обычная таблица, чьи страницы попали в кеш: используются другие структуры индексов, версии строк и оптимистическое согласование транзакций.

**Пример подходящей нагрузки:** много коротких операций добавления и изменения заказов, конкурирующих за горячие строки или страницы. Неподходящая исходная мотивация — «любой большой отчёт должен стать быстрее». Для аналитических сканирований сначала рассматривайте запросы, модель и columnstore.

Два инструмента можно применять отдельно: memory-optimized таблицы и нативно скомпилированные процедуры. Обычный T-SQL может обращаться к таблицам в памяти, а native-процедура в версии 2014 имеет существенно более узкий поддерживаемый язык.

Читайте подразделы последовательно: архитектура → таблицы и индексы → процедуры → транзакции → миграция. Примеры постоянных объектов требуют отдельной учебной базы, файловой группы и доступной памяти. Они не добавляют объекты в исходный AdventureWorks и здесь не выполнялись. Не переносите ограничения или возможности SQL Server 2016+ на первую реализацию 2014.
