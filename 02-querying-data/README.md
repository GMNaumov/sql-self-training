# Выборка и комбинирование данных

Один бизнес-вопрос часто требует нескольких таблиц. Название товара лежит в `Production.Product`, позиции продажи — в `Sales.SalesOrderDetail`, дата заказа — в `Sales.SalesOrderHeader`. Соединения восстанавливают связи, агрегаты превращают строки операций в показатели, а подзапросы и CTE помогают выразить этапы решения.

**Пример постановки:** «Сколько единиц каждого товара продано в январе?» Сначала определите строку результата: один товар. Затем выберите заказы января, соедините позиции по `SalesOrderID`, сгруппируйте по `ProductID` и сложите `OrderQty`. Название добавляйте по ключу товара. Если нужны товары без продаж, понадобится внешнее соединение.

Главный навык раздела — контролировать количество строк. Отношение один-ко-многим закономерно размножает строку родителя. Это не ошибка движка; ошибкой становится суммирование родительского показателя после такого размножения.

**Контроль:** перед написанием запроса проговорите ключ результата и смысл каждого соединения. После — проверьте ноль, одну и несколько связанных строк. Порядок физического выполнения может отличаться от порядка написания SQL.
