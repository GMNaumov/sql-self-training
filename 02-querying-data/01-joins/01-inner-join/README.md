# INNER JOIN

Внутреннее соединение (inner join) возвращает только пары, удовлетворяющие `ON`. Оно подходит, когда для результата необходимы оба объекта: продажа и существующий товар.

```sql
SELECT d.SalesOrderID, p.Name, d.OrderQty, d.LineTotal
FROM Sales.SalesOrderDetail AS d
INNER JOIN Production.Product AS p
  ON p.ProductID = d.ProductID
WHERE d.OrderQty >= 2;
```

Сначала мысленно сопоставьте каждой позиции её товар; затем оставьте позиции с количеством от двух. `LineTotal` — сумма позиции с учётом её скидки; не путайте её с полной суммой заказа, включающей другие компоненты.

Если товар 707 встречается в десяти позициях, его имя появится десять раз. Это десять продаж, а не дубликаты товара, которые нужно удалить `DISTINCT`. Чтобы получить список проданных товаров, задача должна явно требовать уникальные товары либо проверку существования продажи.

Сравнение двух `NULL` через `=` не даёт совпадения. Наличие внешнего ключа обычно гарантирует существование родителя для заполненного значения, но не делает связь взаимно однозначной: у одного товара много позиций.

**Упражнение.** Почему запрос без условия `ON` нельзя «починить» фильтром только по `OrderQty`? Условие количества не определяет, какой товар принадлежит позиции. Нужно равенство ключей. Следите за алиасами: `p.ProductID = p.ProductID` не связывает таблицы.
