# Соединения таблиц

Соединение (join) сопоставляет строки источников по условию. Для заказа с тремя позициями соединение заголовка с позициями даст три строки. Значения даты и покупателя заголовка повторятся в каждой из них.

```sql
SELECT h.SalesOrderID, h.OrderDate, d.ProductID, d.OrderQty
FROM Sales.SalesOrderHeader AS h
JOIN Sales.SalesOrderDetail AS d
  ON d.SalesOrderID = h.SalesOrderID;
```

`h` и `d` — псевдонимы. Предложение `ON` указывает правило соответствия, здесь равенство идентификаторов заказа. Один `JOIN` не означает одну выходную строку. Уникальность и количество зависят от данных и ключей.

`INNER JOIN` оставляет совпадения. `LEFT JOIN` дополнительно сохраняет все строки слева. `CROSS JOIN` строит все пары. Самосоединение использует одну таблицу в двух ролях. `APPLY` вычисляет правый табличный источник с учётом строки слева.

**Ошибка:** соединять по похожим названиям вместо ключей. Два клиента с одинаковым именем не являются одним клиентом. Отдельно проверяйте составные ключи: если связь задают два столбца, пропуск одного может создать ложные совпадения.

**Самопроверка.** Что получится при соединении заказа с двумя платежами и тремя позициями напрямую? До шести комбинаций. Для сумм платежи и позиции часто нужно сначала агрегировать отдельно до уровня заказа.
