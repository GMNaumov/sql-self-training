# CROSS APPLY и OUTER APPLY

`APPLY` позволяет правому табличному выражению использовать значения текущей строки слева. `CROSS APPLY` сохраняет только строки с результатом справа; `OUTER APPLY` сохраняет и строки, для которых правая часть пуста.

**Задача:** показать для каждого товара последнюю позицию заказа по идентификатору заказа.

```sql
SELECT p.ProductID, p.Name, lastSale.SalesOrderID
FROM Production.Product AS p
OUTER APPLY
(
    SELECT TOP (1) d.SalesOrderID
    FROM Sales.SalesOrderDetail AS d
    WHERE d.ProductID = p.ProductID
    ORDER BY d.SalesOrderID DESC, d.SalesOrderDetailID DESC
) AS lastSale;
```

Для товара без продаж `SalesOrderID` будет `NULL`. При замене на `CROSS APPLY` товар исчезнет. Второй ключ сортировки определяет выбор позиции внутри заказа. Идентификатор не является универсальной заменой времени: если требуется последняя продажа именно по дате, соедините заголовки и сортируйте по `OrderDate` с разрешением ничьих.

`APPLY` часто используют с табличными функциями и с `TOP N` на группу. Он не обещает физический запуск подзапроса отдельным циклом для каждой строки: оптимизатор выбирает план. Индекс по ключу связи и сортировки может существенно изменить стоимость.

**Самопроверка.** Гарантирует ли `OUTER APPLY` одну строку на товар? Только если правая часть возвращает не больше одной строки, как в этом примере. Без `TOP (1)` она может размножить результат.
