# Обобщённые табличные выражения

Обобщённое табличное выражение (common table expression, CTE) даёт имя результату запроса в пределах одной следующей команды. Оно помогает разбить задачу на понятные этапы, но не создаёт постоянную или временную таблицу.

```sql
;WITH CustomerTotals AS
(
    SELECT CustomerID, SUM(SubTotal) AS Amount
    FROM Sales.SalesOrderHeader
    GROUP BY CustomerID
)
SELECT CustomerID, Amount
FROM CustomerTotals
WHERE Amount > 10000
ORDER BY Amount DESC, CustomerID;
```

На первом этапе считаем сумму товаров по покупателю, на втором фильтруем вычисленную сумму. Начальная точка с запятой завершает предыдущую команду, чтобы `WITH` корректно распознался. После этого `SELECT` имя `CustomerTotals` больше недоступно.

CTE не гарантирует материализацию (materialization), то есть сохранение промежуточного результата. Повторные ссылки могут привести к повторной работе; если результат нужно использовать многократно, сравните план с временной таблицей.

Рекурсивный CTE строит иерархию: начальная часть выбирает корни, рекурсивная — потомков через `UNION ALL`. Например, дерево компонентов изделия в `Production.BillOfMaterials` требует учитывать сроки действия и защищаться от циклов. По умолчанию действует ограничение 100 рекурсивных шагов; `OPTION (MAXRECURSION ...)` меняет его для команды, но не исправляет ошибочную связь.

**Самопроверка.** Можно ли выполнить два независимых `SELECT` из одного CTE? Нет. Повторите определение либо сохраните результат в `#temp`.

## Рекурсия на маленьком дереве

Этот самостоятельный пример моделирует категорию товаров и вложенные категории, не требует создания объектов и помогает понять переход от родителя к детям:

```sql
;WITH Nodes AS
(
    SELECT NodeID, ParentID, Caption
    FROM (VALUES (1, CAST(NULL AS int), N'Каталог'),
                 (2, 1, N'Велосипеды'),
                 (3, 1, N'Аксессуары'),
                 (4, 2, N'Горные')) AS v(NodeID, ParentID, Caption)
), Tree AS
(
    SELECT NodeID, ParentID, Caption, 0 AS Depth
    FROM Nodes WHERE ParentID IS NULL
    UNION ALL
    SELECT n.NodeID, n.ParentID, n.Caption, t.Depth + 1
    FROM Tree AS t
    JOIN Nodes AS n ON n.ParentID = t.NodeID
)
SELECT NodeID, Caption, Depth
FROM Tree
ORDER BY Depth, NodeID
OPTION (MAXRECURSION 10);
```

Начальная часть даёт корень глубины 0, следующий шаг — узлы 2 и 3 глубины 1, затем узел 4 глубины 2. Когда детей нет, новые строки не появляются и рекурсия завершается. Ограничение защищает от бесконечного обхода, но цикл в реальной модели нужно отдельно обнаруживать и исправлять. Для большой иерархии важен индекс связи с родителем.
