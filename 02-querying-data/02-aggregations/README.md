# Агрегирование данных

Агрегат (aggregate) сворачивает несколько значений в одно: `SUM` складывает, `AVG` усредняет, `MIN` и `MAX` ищут границы, `COUNT` считает. `GROUP BY` задаёт, для каких групп выполнять вычисления.

```sql
SELECT CustomerID, COUNT(*) AS OrderCount,
       SUM(SubTotal) AS GoodsAmount
FROM Sales.SalesOrderHeader
WHERE OrderDate >= '20140101' AND OrderDate < '20150101'
GROUP BY CustomerID
HAVING COUNT(*) >= 3
ORDER BY GoodsAmount DESC, CustomerID;
```

Строка результата — один покупатель. `WHERE` отбирает исходные заказы 2014 года; `HAVING` оставляет группы минимум с тремя заказами. `SubTotal` — сумма товаров без налога и доставки; `TotalDue` выражает другую метрику.

Выбранный столбец должен быть частью ключа группировки или аргументом агрегата. Запрос не может произвольно выбрать `SalesOrderID` из группы покупателя: у него несколько заказов.

`COUNT(*)` на пустом наборе без группировки даст 0; `SUM` — `NULL`. С `GROUP BY` отсутствующая группа вообще не появится. Для вывода нулей всем покупателям начните с таблицы покупателей и используйте внешнее соединение.

**Ошибка:** считать среднюю цену товара как `AVG(UnitPrice)` для средней цены проданной единицы. При разных количествах нужна взвешенная формула: `SUM(UnitPrice * OrderQty) / NULLIF(SUM(OrderQty), 0)`, с согласованным учётом скидок.

**Проверка вручную:** две покупки по 1 и 9 единиц с ценами 100 и 200 дают взвешенную цену 190, а простое среднее — 150.

## Как читать порядок вычислений

Упрощённый логический порядок запроса: `FROM` и соединения → `WHERE` → `GROUP BY` → `HAVING` → выражения `SELECT` и оконные расчёты → `DISTINCT` → итоговая сортировка и ограничение выдачи. Поэтому `WHERE` не может проверять ещё не рассчитанный агрегат группы, а `HAVING COUNT(*) >= 3` может. Это порядок понимания результата, не обещание физического обхода таблиц: оптимизатор вправе переставлять операции, сохраняя смысл.

**Упражнение.** Требуются покупатели с суммой заказов больше 10000, учитывая только заказы 2014 года. Год относится к `WHERE`, сумма — к `HAVING SUM(SubTotal) > 10000`. Если отфильтровать сначала только отдельные заказы дороже 10000, получится другая задача.
