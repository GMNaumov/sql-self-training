# OLTP и OLAP

OLTP (online transaction processing) обслуживает частые короткие операции: оформить заказ, изменить адрес, проверить остаток. OLAP (online analytical processing) рассматривает большие наборы для анализа: выручка за три года по странам и категориям.

| Признак | OLTP | Аналитика |
|---|---|---|
| Типичная работа | Несколько строк по ключу | Агрегаты по множеству строк |
| Модель | Часто нормализованная | Часто измерительная |
| Приоритет | Корректная конкурентная запись | Согласованные метрики и история |

**Пример запроса DW:**

```sql
USE AdventureWorksDW2014;
SELECT d.CalendarYear, SUM(f.SalesAmount) AS SalesAmount
FROM dbo.FactInternetSales AS f
JOIN dbo.DimDate AS d ON d.DateKey = f.OrderDateKey
GROUP BY d.CalendarYear
ORDER BY d.CalendarYear;
```

Здесь год берётся из календарного измерения, а сумма — из строк интернет-продаж. Отчёт не меняет заказы и не обслуживает корзину. `SalesAmount` — показатель в модели демонстрационной базы; для реального проекта дополнительно проверяют валюту и бизнес-смысл.

OLAP не обязательно означает именно SSAS-куб: аналитические SQL-запросы по DW тоже относятся к аналитической нагрузке. OLTP и аналитика могут сосуществовать, но тяжёлые сканирования конкурируют с записью за CPU, память и I/O.

**Самопроверка.** Почему нельзя безусловно запускать годовой отчёт в основной базе в час пик? Он может мешать критичным операциям; рассматривайте изоляцию нагрузки, индексы, копию или отдельное хранилище.
