# Промежуточная область и ETL

ETL (extract, transform, load) извлекает данные, преобразует их и загружает в целевую модель. Staging — промежуточная область, где можно сохранить входной срез, проверить формат и отделить проблемы источника от изменений хранилища.

**Пример загрузки заказов:** извлечь изменения с контрольной отметки; записать пакет с `BatchID`; проверить типы, обязательные ключи и повторы; загрузить версии измерений; сопоставить их ключи; загрузить факты; сверить количество и суммы; только после успеха продвинуть контрольную отметку.

Идемпотентность означает, что повтор пакета после сбоя не создаёт повторные продажи. Для факта нужен устойчивый ключ источника, например номер заказа и позиции, а для пакета — состояние и журнал этапов. Проверка «этот файл уже видели» недостаточна, если один файл может меняться.

Инкрементальная загрузка должна учитывать одинаковые отметки времени, удаления, запоздавшие события и исправления прошлых периодов. Простое `ModifiedDate > @LastDate` может пропустить строки с равной меткой или задним числом; нужен договор с источником, ключ для разрешения равенств и иногда окно повторной обработки.

**Контроль качества:** число извлечённых, принятых, отклонённых и загруженных строк должно объясняться; сумма продаж сверяется на согласованном срезе. Отклонённые строки сохраняют с причиной, а не бесследно пропускают.

**Ошибка:** выполнять truncate и полную загрузку в отчётную таблицу без публикационного барьера. Пользователь может увидеть пустое или частично загруженное состояние. Подготовьте транзакционную публикацию или переключение проверенного набора.
