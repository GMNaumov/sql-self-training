# Суррогатные ключи и медленно меняющиеся измерения

Суррогатный ключ (surrogate key) — технический идентификатор строки измерения. Бизнес-ключ приходит из источника, например код товара. Один бизнес-ключ может иметь несколько исторических версий, поэтому эти ключи не взаимозаменяемы.

Медленно меняющиеся измерения (slowly changing dimensions, SCD) описывают историю признаков. Type 1 перезаписывает значение: исправили опечатку. Type 2 добавляет новую версию с отдельным суррогатным ключом и интервалом действия: клиент сменил регион, но старые продажи должны сохранить прежний контекст.

**Пример.** Клиент C42 жил в Москве до 1 июля, потом в Казани. Измерение получает строки с ключами 101 и 205. Продажа 30 июня ссылается на 101, 2 июля — на 205. Отчёт по историческому региону не должен переписать июнь в Казань.

Интервалы удобно делать полуоткрытыми `[ValidFrom, ValidTo)`. При загрузке факта ищите версию по бизнес-ключу и времени события. Должна находиться ровно одна строка. Две — перекрытие интервалов, ноль — пробел или поздно пришедшее измерение.

В `DimProduct` AdventureWorksDW есть поля `StartDate`, `EndDate`, `Status`; изучите их фактические значения и используемую модель, не считайте любую дату автоматически универсальным SCD-правилом.

**Ошибка:** соединять факт с измерением только по бизнес-коду без выбора версии. Это может размножить продажи. Для неизвестных участников предусмотрите специальный ключ и последующее уточнение, сохраняя контроль загрузки.

**Самопроверка.** Нужен ли Type 2 для исправления неверной буквы? Обычно достаточно Type 1, если бизнес не требует хранить именно историю исправления текста.
