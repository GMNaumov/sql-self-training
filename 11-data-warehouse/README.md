# Аналитические хранилища данных

Хранилище данных (data warehouse, DW) организует сведения для анализа, часто собирая историю из нескольких систем. В отличие от оформления конкретного заказа, отчёт должен сопоставлять периоды, категории, страны и показатели с устойчивыми определениями.

**Сквозной пример.** Руководитель хочет продажи по месяцу и категории. OLTP хранит нормализованные заказы и позиции. DW хранит факт продажи, ключи продукта и даты и согласованные меры. Пользователю отчёта не нужно каждый раз заново разбирать операционную схему.

Самое важное решение — зерно (grain): что означает одна строка факта. Если это строка заказа, сумма строки и сумма всего заказа не должны смешиваться как одинаковые меры. Затем выбирают измерения, историю, ключи и загрузку.

В разделе используем `AdventureWorksDW2014`, прежде всего `FactInternetSales`, `DimProduct`, `DimCustomer` и `DimDate`. Наличие факта интернет-продаж не означает полноту всех каналов компании: для продаж посредникам есть другой факт. Численные бизнес-выводы делают после выполнения и проверки данных, которого здесь пока нет.
