# Таблицы фактов и измерений

Факт (fact) хранит измеряемое событие и ссылки на контекст. Измерение (dimension) хранит описательные признаки для фильтрации и группировки. `FactInternetSales` содержит продажи; `DimProduct` описывает продукты. Один продукт связан со многими строками факта.

```sql
SELECT p.EnglishProductName, SUM(f.OrderQuantity) AS Qty,
       SUM(f.SalesAmount) AS Amount
FROM dbo.FactInternetSales AS f
JOIN dbo.DimProduct AS p ON p.ProductKey = f.ProductKey
GROUP BY p.ProductKey, p.EnglishProductName;
```

Контекст — `AdventureWorksDW2014`. Группировка по ключу и названию не склеивает разные продукты с одинаковым именем. Перед соединением убедитесь, что ключ измерения уникален; иначе сумма размножится.

Аддитивная мера складывается по всем нужным измерениям, например количество продаж при согласованной единице. Полуаддитивная — только по части: остаток на конец дня нельзя суммировать по дням как продажу. Неаддитивная — отношение или процент: среднюю скидку нужно рассчитывать из подходящих числителя и знаменателя, а не усреднять проценты групп.

Факты бывают транзакционные, периодические снимки и накапливающие снимки этапов процесса. Например, ежедневный остаток и строка продажи — разные события с разным зерном. Возможен факт без числовых мер для фиксации посещения или участия.

**Ошибка:** складывать суммы в разных валютах без правила пересчёта. Наличие столбца `Amount` не определяет универсальную бизнес-метрику.

**Самопроверка.** Где хранить категорию продукта? В описательной модели продукта или связанных измерениях, а не как самостоятельно суммируемую меру.
