# Динамический SQL

Динамический SQL строит текст команды во время выполнения. Он нужен, например, при выборе имени столбца сортировки или динамическом списке столбцов отчёта. Значения параметризуйте, а имена объектов проверяйте по разрешённому списку.

```sql
DECLARE @sql nvarchar(max) = N'
SELECT ProductID, Name, ListPrice
FROM Production.Product
WHERE ListPrice >= @MinPrice
ORDER BY ProductID;';
EXEC sys.sp_executesql @sql,
     N'@MinPrice decimal(12,2)', @MinPrice = 1000;
```

Число передаётся отдельно от SQL-текста. Это предотвращает интерпретацию значения как команды и помогает повторно использовать план. Конкатенация пользовательской строки в `WHERE` допускает SQL injection — изменение смысла команды через ввод.

Имя таблицы или столбца нельзя передать обычным параметром вместо синтаксического идентификатора. Если разрешены только `Name` и `ListPrice`, сначала проверьте выбор, затем примените `QUOTENAME` и добавьте результат к тексту. `QUOTENAME` экранирует идентификатор, но не решает вопрос, разрешён ли пользователю этот объект.

Динамический пакет имеет свою область переменных: переменная внешнего пакета недоступна без передачи. Доступ к локальной `#temp`, созданной снаружи, возможен в том же сеансе; таблица, созданная внутри динамического пакета, после его завершения обычно уже недоступна вызывающему коду.

**Ошибка:** считать процедуру защищённой от инъекции лишь потому, что текст находится внутри процедуры. Опасна именно непроверенная сборка текста.
