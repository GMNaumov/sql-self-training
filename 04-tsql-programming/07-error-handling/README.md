# Обработка ошибок

`TRY...CATCH` передаёт управление в обработчик при многих ошибках выполнения. В обработчике доступны `ERROR_NUMBER()`, `ERROR_MESSAGE()` и другие сведения. Он не перехватывает абсолютно всё: например, ошибку синтаксиса в том же пакете нельзя превратить в обычную ветвь выполнения.

```sql
SET XACT_ABORT ON;
BEGIN TRY
    BEGIN TRANSACTION;
    -- Здесь должны находиться связанные изменения учебных таблиц.
    DECLARE @Result int = 1 / 0;
    COMMIT TRANSACTION;
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
    THROW;
END CATCH;
```

Пример намеренно вызывает деление на ноль. `XACT_STATE()` возвращает 0 при отсутствии транзакции, 1 для активной допускающей commit и −1 для транзакции, которую можно только откатить. `THROW;` повторно передаёт исходную ошибку вызывающему коду и доступен в 2014.

Шаблон предполагает, что код владеет транзакцией и не вызван внутри чужой. Вложенные `BEGIN TRAN` не создают независимые транзакции; полный `ROLLBACK` откатывает всю внешнюю работу. Для переиспользуемой процедуры нужен отдельный договор о владении и, где уместно, savepoint.

`SET XACT_ABORT ON` делает поведение многих ошибок более предсказуемым для транзакций, но не отменяет обработчик. `RAISERROR` и `THROW` различаются, в частности по взаимодействию с `XACT_ABORT`.

**Ошибка:** поймать ошибку, напечатать текст и завершиться «успешно». Приложение должно получить достоверный сигнал о неудаче; запись в журнал не заменяет повторную передачу ошибки.
