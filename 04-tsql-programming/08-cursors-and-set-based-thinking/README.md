# Курсоры и множественный подход

Множественный подход (set-based processing) описывает преобразование набора сразу. Курсор (cursor) читает строки последовательно и выполняет действия для каждой. SQL Server особенно хорошо оптимизирует операции над наборами, но последовательная работа иногда нужна для внешнего API или административных команд.

```sql
CREATE TABLE #Prices(ProductID int PRIMARY KEY, Price decimal(12,2));
INSERT INTO #Prices VALUES (707,100), (708,200), (709,0);
UPDATE #Prices
SET Price = Price * 1.05
WHERE Price > 0;
SELECT ProductID, Price FROM #Prices ORDER BY ProductID;
```

Получатся цены 105, 210 и 0. Для этой операции не нужно объявлять курсор, извлекать товар и обновлять его по одному. Единая команда также уменьшает количество обращений клиента к серверу.

У курсора есть этапы `DECLARE`, `OPEN`, `FETCH`, `CLOSE`, `DEALLOCATE`; проверять нужно `@@FETCH_STATUS`. Если последовательный обход действительно необходим, ограничивайте столбцы и число строк и рассматривайте `LOCAL FAST_FORWARD` для чтения вперёд. Режим выбирают по требованиям, а не как универсальное ускорение.

Одна гигантская команда тоже может быть неудобна: миллионы изменений удерживают блокировки и увеличивают журнал. Тогда полезна обработка порциями по устойчивому ключу с отдельными транзакциями и контрольными точками приложения.

**Самопроверка.** Нарастающий итог обязательно требует курсора? Нет: в SQL Server 2014 есть оконные агрегаты. Сначала ищите выразительное решение над набором, затем измеряйте.
