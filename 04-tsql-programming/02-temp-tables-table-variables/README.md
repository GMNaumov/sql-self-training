# Временные таблицы и табличные переменные

Локальная временная таблица `#T` доступна в своём сеансе и хранится с участием `tempdb`. Табличная переменная `@T` живёт в области пакета или модуля; она также может использовать `tempdb` и не является гарантированно «таблицей только в оперативной памяти».

```sql
SELECT CustomerID, SUM(SubTotal) AS Amount
INTO #CustomerTotals
FROM Sales.SalesOrderHeader
GROUP BY CustomerID;
CREATE UNIQUE CLUSTERED INDEX CX_CustomerTotals
ON #CustomerTotals(CustomerID);
SELECT CustomerID, Amount
FROM #CustomerTotals WHERE Amount > 10000;
DROP TABLE #CustomerTotals;
```

`SELECT INTO` создаёт таблицу по структуре результата и наполняет её. Уникальный индекс соответствует одной строке на покупателя. Временный результат можно использовать несколькими следующими командами, в отличие от CTE.

В SQL Server 2014 у табличных переменных нет обычной статистики распределения, и оптимизатор часто оценивает их как одну строку. Для большой промежуточной таблицы это может привести к неудачным соединениям. Отложенной компиляции табличных переменных из SQL Server 2019 здесь нет. При необходимости сравнивайте `#temp`, индексы и точечный `OPTION (RECOMPILE)`.

**Ошибка:** выбирать `@table` только из-за малого числа строк в одном тесте. Важны повторное использование, соединения, индексы, распределение и план. Созданная внутри процедуры `#temp` обычно удаляется по её завершении; глобальные `##` имеют другой жизненный цикл и требуют осторожности при одновременной работе.
