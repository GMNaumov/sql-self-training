# Базы данных, схемы и таблицы

Сервер содержит базы (databases), база — схемы (schemas), схема — объекты, включая таблицы. Схема группирует имена и служит границей назначения разрешений. `Sales` и `Production` в AdventureWorks — схемы, а не отдельные базы и не пользователи.

```sql
USE AdventureWorks2014;
GO
SELECT TOP (5) SalesOrderID, OrderDate
FROM Sales.SalesOrderHeader
ORDER BY SalesOrderID;

SELECT s.name AS SchemaName, t.name AS TableName
FROM sys.tables AS t
JOIN sys.schemas AS s ON s.schema_id = t.schema_id
ORDER BY s.name, t.name;
```

Первый запрос читает заголовки заказов. Второй читает каталог (catalog): системные сведения об устройстве базы. `AS` вводит короткий псевдоним. Каталог не является содержимым заказов; он описывает объекты.

Полное трёхчастное имя — `AdventureWorks2014.Sales.SalesOrderHeader`. Внутри выбранной базы обычно достаточно `Sales.SalesOrderHeader`. Явное имя схемы делает код понятнее и исключает зависимость поиска объекта от схемы пользователя по умолчанию.

**Типичная ошибка:** писать `dbo.Product` по привычке. `dbo` — распространённая схема, но нужный товар находится в `Production.Product`. Ошибка «Invalid object name» может означать неверную базу или схему, а не отсутствие данных.

**Самопроверка.** Две таблицы `Sales.Item` и `Warehouse.Item` могут существовать в одной базе? Да: схемы создают разные пространства имён. Их структура и данные могут различаться.

## Представление как сохранённый запрос

Представление (view) хранит определение запроса и используется как табличный источник. Например, для отдельной учебной базы можно создать интерфейс каталога:

```sql
CREATE VIEW dbo.LabProductCatalog
AS
SELECT ProductID, Name, ListPrice
FROM AdventureWorks2014.Production.Product
WHERE ListPrice > 0;
GO
SELECT ProductID, Name
FROM dbo.LabProductCatalog
WHERE ListPrice >= 1000
ORDER BY ProductID;
```

`CREATE VIEW` начинает отдельный пакет. Обычное представление не сохраняет копию строк: последующий запрос видит данные источника согласно изоляции. Права межбазового чтения нужно подготовить отдельно. Порядок задаёт конечный `ORDER BY`, а не «порядок внутри view». Индексируемые представления — специальный механизм с дополнительными ограничениями, а не свойство любого view; данный межбазовый пример к ним не относится.

**Самопроверка.** Если цена товара в источнике изменилась, нужно ли пересоздать обычное представление? Нет, определение запроса осталось тем же. Смена структуры источника — другой вопрос и требует проверки зависимостей.
