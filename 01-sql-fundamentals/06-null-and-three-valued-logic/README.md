# NULL и трёхзначная логика

`NULL` означает отсутствующее или неизвестное значение. Это не ноль и не пустая строка. У товара может быть неизвестен цвет; цена ноль при этом может быть известной ценой. Обычное сравнение с неизвестным даёт `UNKNOWN`, то есть третье логическое значение помимо `TRUE` и `FALSE`.

```sql
SELECT ProductID, Name, Color
FROM Production.Product
WHERE Color IS NULL;

SELECT ProductID, Name
FROM Production.Product
WHERE Color <> N'Red' OR Color IS NULL;
```

Первый запрос выбирает товары без цвета. Второй — известные не-красные цвета и неизвестные. Только `Color <> N'Red'` не выберет `NULL`: `WHERE` пропускает исключительно `TRUE`. Используйте `IS NULL`, а не `= NULL`; не меняйте настройки сессии ради иного поведения.

`COALESCE(Color, N'Не указан')` возвращает первый аргумент, не равный `NULL`. Это удобно для отображения, но подстановка не восстанавливает неизвестный факт. Агрегаты `SUM` и `AVG` пропускают `NULL`; `COUNT(*)` считает строки, `COUNT(Color)` — только известные цвета.

**Пример вручную.** Для значений 10, 20 и `NULL` среднее равно 15, а не 10. Если бизнес считает пропуск нулём, это отдельное правило, которое нужно явно записать.

**Ловушка:** `NOT IN` с `NULL` в подзапросе может исключить ожидаемые строки. Для проверки отсутствия связанной записи обычно яснее `NOT EXISTS`; разберём его в подзапросах.
