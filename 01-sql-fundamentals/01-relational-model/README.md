# Реляционная модель данных

Таблица (table) состоит из строк и столбцов. Строка (row) описывает один объект или событие; столбец (column) — один его признак. У всех строк один набор столбцов. В таблице товаров нельзя считать третью строку постоянным адресом велосипеда: строки не имеют гарантированного порядка.

Ключ (key) позволяет отличить строку от остальных. В `Production.Product` роль идентификатора выполняет `ProductID`. Название не всегда подходит для ключа: его могут исправить. Внешний ключ (foreign key) связывает объекты: позиция заказа хранит идентификатор товара, вместо того чтобы каждый раз копировать все его характеристики.

```sql
SELECT ProductID, Name, ListPrice
FROM Production.Product
WHERE ProductID = 707;
```

Если такой товар есть, условие выбирает его независимо от того, где он физически лежит. Запрос возвращает таблицу результата, которая может быть пустой. Это нормальный исход, а не обязательно ошибка.

Реляционная теория работает с отношениями без повторяющихся кортежей; SQL по умолчанию допускает повторяющиеся строки результата. Поэтому нельзя автоматически считать любую выборку множеством уникальных объектов.

**Задача.** Можно ли поместить список телефонов через запятую в один столбец клиента? Технически можно записать строку, но искать отдельный телефон и обеспечивать уникальность неудобно. Отдельная таблица телефонов с идентификатором клиента лучше выражает связь один-ко-многим. В разделе проектирования разберём это как нормализацию.
