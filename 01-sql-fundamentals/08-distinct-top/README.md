# DISTINCT, TOP и ограничение результата

`DISTINCT` убирает повторяющиеся комбинации всех выбранных столбцов. `TOP` ограничивает число строк. Это разные операции: одна определяет уникальность результата, другая его размер.

```sql
SELECT DISTINCT Color
FROM Production.Product;

SELECT TOP (5) ProductID, Name, ListPrice
FROM Production.Product
ORDER BY ListPrice DESC, ProductID;
```

Первый запрос перечисляет встречающиеся цвета; несколько `NULL` образуют одну строку результата. Второй выбирает пять самых дорогих товаров, а при равной цене отдаёт приоритет меньшему `ProductID`. Без `ORDER BY` это были бы произвольные пять строк.

Если бизнес просит все товары с ценой на границе пятого места, возможен `TOP (5) WITH TIES ... ORDER BY ListPrice DESC`. Тогда строк может оказаться больше пяти. Добавление уникального `ProductID` в эту сортировку устранит равенство ключей и изменит смысл ничьей.

В SQL Server 2014 есть постраничная выдача `ORDER BY ProductID OFFSET 0 ROWS FETCH NEXT 5 ROWS ONLY`. Сортировка обязательна. При изменениях данных между запросами страницы могут смещаться; позже для устойчивой навигации пригодится отбор по последнему ключу.

**Ошибка:** добавлять `DISTINCT` после неверного соединения, чтобы скрыть лишние строки. Сначала объясните, откуда взялись повторы. Если товары действительно разные, одинаковые отображаемые названия не делают их одним товаром.

**Упражнение.** `DISTINCT Color, Size` перечисляет цвета или пары? Пары. Один цвет может встретиться несколько раз с разными размерами.
