# Безопасность SQL Server

Безопасность данных начинается с определения субъектов и разрешённых операций. Аутентификация отвечает «кто подключился», авторизация — «что ему разрешено». Шифрование защищает определённый канал или носитель, аудит фиксирует действия. Одно средство не заменяет остальные.

**Пример.** Веб-приложение должно оформлять заказы, но не менять настройки сервера и не читать зарплаты сотрудников. Отдельная роль с разрешением выполнения нужных процедур даёт более узкий доступ, чем `sysadmin` или `db_owner`. При этом динамический SQL и межбазовые обращения требуют отдельной проверки прав.

Изучайте входы, пользователей и роли перед цепочками владения. Затем разделяйте защиту файлов, значений, резервных копий и подключения. Для каждого ключа заранее определите резервирование и восстановление: потерянный ключ может сделать данные недоступными законному владельцу.

В SQL Server 2014 нет Always Encrypted, Dynamic Data Masking и встроенной Row-Level Security из SQL Server 2016. Не предлагайте их как доступные функции этого проекта. Все примеры выдачи прав предназначены для будущей отдельной лаборатории, а не для текущей конфигурации компьютера.
