# Шифрование сетевых подключений

Шифрование подключения защищает передачу между драйвером клиента и SQL Server. TLS использует сертификат сервера: клиент должен проверить доверенную цепочку и совпадение имени. Шифрование без проверки личности сервера не даёт полноценной защиты от подмены.

**Пример.** Приложение подключается по имени `sql-lab.example.test`; сертификат должен быть действителен для этого имени и доверен клиенту. Подключение по IP вместо имени может нарушить проверку. Учётная запись службы должна иметь необходимые права на закрытый ключ сертификата.

В SQL Server Configuration Manager сертификат и требования шифрования настраиваются для протоколов экземпляра. В драйвере проверяются параметры шифрования и проверки сертификата; их названия и значения по умолчанию зависят от конкретного драйвера. Не переносите современные значения по умолчанию на старый SQL Native Client.

```sql
SELECT session_id, encrypt_option, net_transport
FROM sys.dm_exec_connections
WHERE session_id = @@SPID;
```

Проверяйте отдельное сетевое подключение: локальный shared memory не моделирует трафик приложения. `encrypt_option` сообщает о шифровании соединения, но сам по себе не доказывает корректную проверку сертификата клиентом.

SQL Server 2014 для TLS 1.2 требует поддерживаемой сборки/обновлений, совместимых ОС и драйверов. Перед настройкой сверяйте конкретную матрицу поддержки; изменение системных протоколов здесь не выполняется.

**Ошибка:** постоянно применять доверие любому сертификату ради устранения ошибки подключения. В лаборатории это скрывает проблему, которую нужно решить цепочкой доверия и правильным именем.
