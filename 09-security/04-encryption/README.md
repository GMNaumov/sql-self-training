# Шифрование и защита данных

Шифрование (encryption) делает данные нечитаемыми без ключа, но нужно выбрать защищаемый участок. TDE защищает дисковые файлы, шифрование столбцов — отдельные значения, backup encryption — копию, TLS — передачу по сети.

**Пример угроз:** украденный диск требует защиты данных на носителе; перехваченное сетевое подключение — TLS; пользователь с законным `SELECT` на TDE-базе всё равно видит расшифрованные строки. У каждой угрозы свой механизм и граница защиты.

В SQL Server 2014 backup encryption уже доступно. Always Encrypted относится к более поздним версиям и здесь не применяется. Для TDE есть важное ограничение первой версии In-Memory OLTP: файлы `MEMORY_OPTIMIZED_DATA` не защищаются так же, как обычные файлы данных.

Планируйте жизненный цикл ключей: создание, хранение, доступ, резервирование, перенос и восстановление. До включения шифрования в будущем стенде проверьте сценарий восстановления на другом экземпляре. Сам факт наличия сертификата без закрытого ключа и нужного пароля может быть недостаточен.

**Контроль:** сформулируйте, кто не должен прочитать данные, при каких условиях и где остаётся открытый текст. Шифрование не исправляет чрезмерные права и SQL injection.
