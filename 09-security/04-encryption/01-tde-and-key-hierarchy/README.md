# Прозрачное шифрование данных (TDE) и иерархия ключей

Прозрачное шифрование данных (transparent data encryption, TDE) шифрует обычные файлы данных и журнал при записи. Приложение продолжает отправлять привычные запросы, а законный читатель получает открытые значения. Это защита носителя, а не запрет чтения администратором.

Типовая иерархия: service master key экземпляра защищает database master key в `master`; тот защищает закрытый ключ сертификата; сертификат защищает database encryption key (DEK) пользовательской базы; DEK шифрует файлы. Возможны другие варианты с EKM, но их инфраструктура выходит за начальную лабораторию.

```sql
SELECT DB_NAME(database_id) AS DatabaseName,
       encryption_state, percent_complete, key_algorithm, key_length
FROM sys.dm_database_encryption_keys;
```

Диагностический запрос не включает TDE. Требуются соответствующие права. Значения состояния интерпретируйте по документации и фазе операции, а не как логический признак «не ноль — всё готово».

**Пример восстановления.** Backup TDE-базы перенесён на другой сервер. Сначала восстановите сертификат с закрытым ключом в `master` нового экземпляра, затем базу. Без ключевого материала восстановление не получится.

Для SQL Server 2014: TDE шифрует записи журнала In-Memory OLTP, но файлы группы `MEMORY_OPTIMIZED_DATA` остаются незашифрованными. Это существенная граница защиты. Источник: [TDE и ограничения In-Memory](https://learn.microsoft.com/en-us/sql/relational-databases/security/encryption/transparent-data-encryption).

**Самопроверка.** Шифрует ли TDE трафик между клиентом и сервером? Нет, для этого нужен защищённый сетевой канал.
