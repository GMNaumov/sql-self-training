# Шифрование значений столбцов и резервных копий

Шифрование значений столбцов делает выбранные поля бинарными шифротекстами через функции вроде `EncryptByKey`. Доступ к расшифровке зависит от открытого ключа и разрешений. Поиск, сортировка и индексация таких значений требуют отдельного проектирования; обычное сравнение шифротекста не заменяет сравнение исходного текста.

**Пример.** Номер документа хранится в `varbinary`, ключ защищён сертификатом. Процедура открывает ключ для разрешённой операции, расшифровывает значение и закрывает его. Широкое право чтения бинарного поля и право использования ключа — разные права. Не используйте учебные пароли как реальные секреты.

Backup encryption в SQL Server 2014 защищает файл копии независимо от включения TDE. В подготовленном стенде с сертификатом `LabBackupCert` в `master`:

```sql
BACKUP DATABASE AdventureWorks2014
TO DISK = N'E:\SqlLabBackups\AW_encrypted_01.bak'
WITH CHECKSUM, COMPRESSION,
ENCRYPTION (ALGORITHM = AES_256, SERVER CERTIFICATE = LabBackupCert);
```

До использования экспортируйте сертификат с закрытым ключом и проверьте восстановление на другом сервере. Для restore не добавляют зеркальную опцию расшифровки: экземпляру должен быть доступен соответствующий ключевой материал.

**Ошибка:** скопировать `.bak`, но забыть сертификат. Другая ошибка — считать шифрование backup защитой исходной незашифрованной базы или сетевого канала.

Источник: [шифрование резервных копий, начиная с SQL Server 2014](https://learn.microsoft.com/en-us/sql/relational-databases/backup-restore/backup-encryption).
