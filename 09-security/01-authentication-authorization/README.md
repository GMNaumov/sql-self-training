# Проверка подлинности и авторизация

Аутентификация (authentication) проверяет личность, авторизация (authorization) — разрешение действия. В SQL Server возможны Windows authentication и SQL authentication при соответствующем режиме экземпляра. Режим базы, логин и права на таблицу — разные настройки.

```sql
SELECT ORIGINAL_LOGIN() AS OriginalLogin,
       SUSER_SNAME() AS CurrentServerIdentity,
       USER_NAME() AS CurrentDatabaseUser;
```

Первое значение показывает исходный вход; текущий контекст может отличаться при `EXECUTE AS`. Пользователь базы определяет базовые разрешения. Подключение к экземпляру не даёт автоматически права читать любую базу.

**Пример.** Windows-группа разработчиков имеет вход на сервер. В учебной базе ей соответствует пользователь, включённый в роль только для чтения. Участник проходит Windows-аутентификацию, но попытка `UPDATE` должна быть запрещена. Проверяйте это отдельным тестовым субъектом, а не административным подключением.

SQL-логины требуют управления паролями и безопасного хранения секрета подключения. Не помещайте настоящий пароль в README или репозиторий. Windows authentication часто удобна при доменной инфраструктуре, но её наличие само по себе не означает минимальные права.

**Ошибка:** лечить «permission denied» назначением `sysadmin`. Сначала определите конкретное действие, базу, текущий контекст и нужное разрешение. Политика минимальных привилегий (least privilege) уменьшает последствия ошибки приложения.

**Самопроверка.** Подключение успешно, чтение таблицы запрещено. Какая стадия прошла? Аутентификация прошла; нужно разбирать авторизацию и сопоставление пользователя.
