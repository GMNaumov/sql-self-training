# Отказоустойчивая кластеризация

Failover Cluster Instance (FCI) переносит роль одного SQL-экземпляра между узлами WSFC. Пользователь обращается к виртуальному имени экземпляра. При отказе роли запускаются на другом узле с теми же файлами базы на общем хранилище.

**Пример.** Сервер A вышел из строя, кластер передал диски и SQL-роль серверу B. Подключения разорвались и должны восстановиться. Время включает обнаружение, перенос ресурсов, запуск и восстановление баз по журналу.

FCI защищает экземпляр от ряда отказов узла, но не создаёт независимую историческую копию данных. Общее хранилище остаётся важной зависимостью и должно быть защищено на своём уровне. Ошибочный `DELETE` не отменяется переключением узла.

| Свойство | FCI | AG |
|---|---|---|
| Основная единица | Экземпляр | Набор пользовательских баз |
| Файлы данных | Обычно общие для роли | Отдельные на репликах |
| Читаемая вторая копия | Не является целью FCI | Возможна при настройке |

Комбинации FCI и AG существуют, но их правила переключения сложнее, чем у каждого механизма отдельно. Для курса сначала объясните простой двухузловой сценарий и его точки отказа.

**Самопроверка.** Появляются ли два одновременно пишущих владельца одной FCI-базы? Нет, роль имеет владельца. Кластерная инфраструктура и кворум нужны для согласованного управления, а не для независимого одновременного запуска одинаковой базы на каждом узле.
