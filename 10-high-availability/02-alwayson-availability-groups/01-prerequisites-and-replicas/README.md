# Предварительные требования и реплики доступности

Для типовой AG в SQL Server 2014 нужны совместимые SQL-экземпляры на узлах Windows Server Failover Cluster (WSFC), корректный кворум, сеть, endpoint связи реплик и права служб. Каждая реплика хранит собственные файлы базы; общее хранилище не является обязательным принципом AG.

База должна соответствовать требованиям, включая FULL recovery, и быть подготовлена согласованными backup. Вторичную копию восстанавливают с `NORECOVERY` и присоединяют. Настройка AlwaysOn выполняется на уровне экземпляра и требует отдельной инфраструктурной подготовки.

**Пример плана:** два узла для локальной отказоустойчивости и witness для кворума. Проверьте, переживёт ли кластер потерю одного узла и сетевого пути, а не только остановку SQL-службы. Кворум защищает от конфликтующих решений о владельце роли.

```sql
SELECT ar.replica_server_name, ar.availability_mode_desc,
       ar.failover_mode_desc
FROM sys.availability_replicas AS ar;
```

Это просмотр настроенных реплик. Отсутствие строк может означать отсутствие AG или ограничение видимости; запрос не создаёт инфраструктуру. Текущее состояние ищут в HADR DMV, например `sys.dm_hadr_database_replica_states`.

**Ошибка:** настроить только SQL-часть, забыв DNS, endpoint-порт, firewall, служебные права и кворум. Не проверяйте сеть бесконтрольным отключением в рабочей системе: сначала составьте воспроизводимый план отказа в отдельном стенде.

**Самопроверка.** Переносятся ли логины вместе с AG-базой? Пользователи базы — да, серверные логины требуют отдельной синхронизации.
