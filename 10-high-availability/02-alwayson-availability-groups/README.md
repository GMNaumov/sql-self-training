# AlwaysOn Availability Groups

Группа доступности (availability group, AG) объединяет пользовательские базы с одной основной и вторичными репликами. Основная передаёт записи журнала; вторичные сохраняют и применяют их. Это не общий сетевой диск и не копия всего экземпляра.

В SQL Server 2014 Enterprise возможно до восьми вторичных реплик. Не все из них предназначены для автоматического синхронного переключения. Различайте настройку реплики, фактическую синхронизацию базы и политику failover. Источник о версии: [возможности SQL Server 2014 от Microsoft](https://www.microsoft.com/en-us/sql-server/blog/2014/03/18/sql-server-2014-releases-april-1/).

**Пример.** Основная реплика обслуживает заказы; локальная синхронная готова к аварии узла; удалённая асинхронная предназначена для DR. Отчёт может читать разрешённую secondary, учитывая задержку применения данных. Backup preference — рекомендация для логики заданий, а не автоматическое создание backup.

Логины, Agent jobs, linked servers и многие настройки экземпляра автоматически не переносятся как часть пользовательской базы. Подготовьте их отдельно и проверьте SID и контексты безопасности.

В 2014 нет automatic seeding: начальная подготовка обычно использует backup/restore с `NORECOVERY` либо соответствующую автоматизацию мастера, основанную на передаче данных. Изучите prerequisites, listener и режимы прежде, чем проектировать переключение.
