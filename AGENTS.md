# Контекст проекта

## Назначение

Проект — русскоязычный самоучитель по Microsoft SQL Server для начинающего разработчика. Маршрут должен вести от нулевых знаний SQL до уверенного уровня собеседований в ведущие компании на позиции, связанные с разработкой программного обеспечения.

Обязательные направления:

- SQL и T-SQL: запросы, соединения, изменение данных, программирование, хранимые процедуры, функции и триггеры;
- проектирование баз данных и целостность данных;
- транзакции, блокировки и конкурентный доступ;
- производительность запросов, индексы, статистика и планы выполнения;
- In-Memory OLTP;
- администрирование SQL Server начального и среднего уровня, включая безопасность, резервное копирование, восстановление, мониторинг и высокую доступность;
- аналитические хранилища, аналитический SQL и компоненты BI;
- практика и разбор задач для собеседований.

## Технические ограничения

- Целевая версия: **Microsoft SQL Server 2014 Enterprise**.
- Все примеры и рекомендации должны учитывать возможности и ограничения именно SQL Server 2014. Не переносить без пояснений возможности более новых версий.
- Уровень совместимости демонстрационных баз при работе с SQL Server 2014: `120`, если в материале явно не рассматривается другой сценарий.
- На компьютере доступен локальный экземпляр SQL Server 2014 Enterprise `12.0.2269.0`; подключение к нему через `sqlcmd` подтверждено. Обе демонстрационные базы находятся в состоянии `ONLINE` с совместимостью `120`.
- Учётные данные администратора предоставлены пользователю отдельно. Не записывать пароль в `AGENTS.md`, скрипты, журналы или другие файлы проекта.
- Не устанавливать дополнительные компоненты и не изменять системную конфигурацию без отдельного запроса пользователя. Подготовка `SqlTraining`, In-Memory OLTP, SSAS/SSIS и административные изменения остаются отдельными лабораториями.

## Демонстрационные базы

В корне проекта уже находятся резервные копии, предоставленные Microsoft:

- `AdventureWorks2014.bak` — основная OLTP-база для SQL, T-SQL, проектирования, производительности и администрирования;
- `AdventureWorksDW2014.bak` — аналитическая база для хранилищ данных, измерительного моделирования и аналитических запросов.

Обе базы восстановлены на локальном экземпляре. Не удалять, не перезаписывать и не перемещать исходные `.bak` без явного запроса пользователя.

## Организация материалов

- Язык материалов — русский; технические термины при первом использовании желательно сопровождать английским эквивалентом.
- Каждая тема находится в отдельной папке, её материал — в файле `README.md` этой папки.
- Крупные темы делятся на вложенные папки.
- Имена папок — на английском языке, строчными буквами, с дефисами; числовые префиксы задают порядок обучения.
- Навигация реализуется относительными Markdown-ссылками в `README.md`: корневой файл ведёт к разделам, разделы — к темам.
- При добавлении, удалении или переименовании темы обновлять навигацию родительского раздела и, при необходимости, корневого `README.md`.
- Пользователь явно разрешил наполнить все Markdown-файлы учебным содержанием. Этап создания только структуры завершён; требование сохранять тематические заготовки больше не действует.
- Новые учебные материалы должны быть последовательными, практическими и опираться преимущественно на AdventureWorks2014 и AdventureWorksDW2014.
- Практические задания и разборы внутри Markdown должны содержать условия, решения, пояснения и типичные ошибки. Для начинающего сначала объяснять понятия и ожидаемый смысл результата, затем синтаксис.
- В каждой из 138 конечных тем есть `examples.sql` с тремя пронумерованными сценариями: простой, продвинутый и практический. Для профильных SSAS-тем дополнительно созданы 4 файла `examples.mdx` и 4 файла `examples.dax`. MDX/DAX требуют соответствующей развёрнутой модели Analysis Services и не выполняются в Database Engine.
- Для изменяющих примеров предпочитать локальные временные таблицы либо явно обозначенные постоянные объекты отдельной учебной базы. Не представлять `Lab...` как уже существующие объекты AdventureWorks.
- Указывать предпосылки для постоянных модулей, In-Memory OLTP, BI и команд восстановления. Пути, даты и секреты-обозначения должны быть явно учебными; выходные backup не должны перезаписывать исходные `.bak` проекта.
- Для документации Microsoft проверять применимость именно к 2014: современная страница часто содержит возможности нескольких версий. Ссылки на основные первичные источники собраны в корневом README.md.

## Проверка изменений

Проверять структуру каталогов, относительные ссылки и соответствие материалов SQL Server 2014 статически. Безопасные запросы и примеры с временными объектами дополнительно выполнять на локальном экземпляре. Не запускать автоматически backup/restore, изменения безопасности, HA/DR, Resource Governor и постоянные объекты без необходимых предпосылок. Успешная выборочная проверка не означает выполнение всех сценариев или проверку MDX/DAX.

## Состояние материалов и продолжение работы

- Маршрут включает 16 разделов, от `00-getting-started` до `15-interview-preparation`. Все 169 учебных README.md наполнены русскоязычными объяснениями, практическими сценариями и примерами; AGENTS.md хранит контекст, а не является учебным уроком.
- Точка входа — корневой `README.md`. В крупных темах предусмотрены вложенные разделы со своими оглавлениями и ссылками на родителя.
- Разделы охватывают основы, T-SQL, моделирование, конкурентный доступ, производительность, In-Memory OLTP, администрирование, безопасность, HA/DR, DW, аналитический SQL, SSIS/SSAS/SSRS и собеседования. Раздел 15 содержит условия и разборы задач непосредственно в Markdown.
- Целевые особенности: Database Engine 2014 Enterprise, compatibility 120; SSAS Tabular 2014 — compatibility 1103. Не применять CREATE OR ALTER, DROP IF EXISTS, STRING_AGG, STRING_SPLIT, Query Store, JSON-функции, temporal tables, Always Encrypted и другие поздние возможности как доступные в 2014.
- В In-Memory OLTP учитывать ограничения первой реализации, включая определение индексов при создании таблицы, ограниченный native T-SQL и конфликты оптимистического доступа. В Columnstore различать обновляемый clustered 2014 и read-only nonclustered; в HA не переносить automatic seeding и distributed AG новых версий.
- Не приписывать проекту измеренные планы, времена, чтения или успешные административные операции, если они фактически не выполнялись. Состояние конкретной проверки фиксировать с её областью и ограничениями.
- При добавлении отдельных примеров на локальном SQL Server 2014 успешно выполнены 133 из 138 файлов `examples.sql`. Не запускались три файла постоянных модулей/триггеров из-за отсутствия `SqlTraining`, файл создания индекса в AdventureWorks (во избежание постоянного изменения) и файл SSISDB (каталог отсутствует). Статически проверены все 138 SQL-файлов, наличие трёх уровней, ссылки и отсутствие сохранённого пароля. 4 MDX- и 4 DAX-файла на SSAS не выполнялись: развёрнутые модели не подтверждены.
- Ранее выполненная статическая проверка наполнения от 2026-11-03: проверены все 170 Markdown-файлов (169 README.md и этот AGENTS.md), существование целей 340 относительных ссылок, сохранение исходной навигации, отсутствие незаполненных заготовок, баланс блоков кода и Unicode. В README содержатся 109 блоков SQL; дополнительно просмотрены явные поздние конструкции. Это не полноценный синтаксический анализатор и не выполнение T-SQL. SHA-256 обеих исходных `.bak` до и после работы совпали.
- Следующий этап — расширение лабораторных проверок и подготовка постоянных объектов/BI-моделей только по отдельному запросу. Не устанавливать компоненты автоматически ради валидации материалов.
