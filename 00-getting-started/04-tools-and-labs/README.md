# Инструменты разработчика и организация практики

В SSMS Object Explorer показывает объекты сервера; окно New Query позволяет отправлять T-SQL. Перед выполнением смотрите на имя подключённого экземпляра и выбранную базу. Один и тот же текст сработает по-разному в `master` и `AdventureWorks2014`.

```sql
USE AdventureWorks2014;
GO
SELECT DB_NAME() AS CurrentDatabase;
SELECT TOP (5) ProductID, Name
FROM Production.Product
ORDER BY ProductID;
```

`USE` меняет текущую базу подключения. `GO` — разделитель пакетов, который понимает клиент SSMS; это не команда движка и не часть SQL для отправки через обычный драйвер. Последний запрос читает пять товаров с наименьшими идентификаторами.

Для упражнений с изменением данных используйте временные таблицы `#...` либо отдельную учебную базу, явно созданную в будущем. Не тренируйте `DELETE` на исходных данных AdventureWorks. Сохраняйте условие, свой прогноз, результат и объяснение ошибки. Пока отдельные SQL-файлы не создаём: код расположен в Markdown.

В SSMS различайте Results и Messages: первая вкладка содержит строки, вторая — ошибки и диагностические сообщения. При изучении производительности позже понадобятся Actual Execution Plan и `SET STATISTICS IO, TIME ON`.

**Упражнение.** Уберите `ORDER BY` из примера. Можно ли обещать те же пять товаров? Нет: без сортировки выбор `TOP` не определяет конкретный порядок. Даже если в нескольких запусках результат совпал, это не гарантия.
