# Практика SQL-запросов

В задачах SQL сначала определите одну строку ответа. «Покупатель с тремя заказами» — строка покупателя; «его три последних заказа» — строки заказов. Эта разница определяет группировку, окно и соединения.

**Мини-пример.** У A два заказа с тремя и четырьмя позициями, у B заказов нет. После соединения заголовков с позициями `COUNT(*)` по A даст семь, а не два. Правильный подсчёт заказов идёт по заголовкам либо через явно выбранный уникальный ключ.

Каждую задачу оценивайте по четырём признакам: верная семантика, граничные случаи, объяснимость, разумная стоимость. Временное решение с CTE допустимо, но его имя не доказывает сохранение промежуточного результата. `DISTINCT` допустим по условию, но не как маскировка неверных связей.

Подразделы растут от фильтрации к соединениям, подзапросам и окнам, затем к островам, дубликатам и реляционному делению. Используется AdventureWorks2014, кроме явно самостоятельных наборов `VALUES` и временных таблиц.

**Самопроверка перед сдачей:** пустой вход, один объект, равные даты, неизвестный атрибут и несколько дочерних строк не ломают договор. Порядок результата задан явно, если нужен. Числовые итоги не объявлены измеренными, пока сервер отсутствует.
