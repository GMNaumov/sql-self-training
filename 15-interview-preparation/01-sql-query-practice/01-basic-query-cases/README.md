# Задачи на выборку, фильтрацию и NULL

**Задача 1.** Выведите десять самых дорогих товаров с положительной ценой и неизвестным цветом. При равной цене выбирайте меньший идентификатор. Нужны ровно десять строк, если подходящих достаточно.

```sql
SELECT TOP (10) ProductID, Name, ListPrice
FROM Production.Product
WHERE ListPrice > 0 AND Color IS NULL
ORDER BY ListPrice DESC, ProductID;
```

`IS NULL` проверяет отсутствие цвета, не `= NULL`. Уникальный второй ключ определяет ничьи. `WITH TIES` изменил бы условие о точном количестве; сортировка только по цене не определила бы выбор среди равных.

**Задача 2.** Верните заказы января 2014 года, включая весь последний день.

```sql
SELECT SalesOrderID, OrderDate
FROM Sales.SalesOrderHeader
WHERE OrderDate >= '20140101' AND OrderDate < '20140201'
ORDER BY OrderDate, SalesOrderID;
```

Полуоткрытый интервал не зависит от точности времени. `BETWEEN ... '20140131'` не включает большую часть 31 января при наличии времени. Условие по `YEAR` и `MONTH` менее удобно для индекса по исходной дате.

**Задача 3.** Сколько товаров имеют известный цвет, а сколько всего?

```sql
SELECT COUNT(*) AS AllProducts, COUNT(Color) AS WithColor
FROM Production.Product;
```

Разность — количество строк с `NULL` цвета; пустая строка считалась бы известным значением. Проверьте это вручную на трёх товарах: красный, `NULL`, пустая строка. Ответ: всего 3, известных 2.

**Обсуждение на интервью:** как изменится условие, если пустая строка тоже означает «не указан»? Это дополнительное бизнес-правило, которое нужно явно выразить и согласовать с данными.
