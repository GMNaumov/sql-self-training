# Практика T-SQL

**Условие.** Уменьшите остаток на положительное количество. При нехватке или отсутствии товара операция должна явно сообщить отказ и не создать отрицательный остаток. В отдельной учебной базе заранее нужна `dbo.LabStock(ProductID int PRIMARY KEY, Qty int NOT NULL CHECK(Qty>=0))`.

```sql
CREATE PROCEDURE dbo.TakeLabStock @ProductID int, @Qty int
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;
    IF @Qty IS NULL OR @Qty <= 0
        THROW 50001, N'Количество должно быть положительным', 1;
    BEGIN TRY
        BEGIN TRANSACTION;
        UPDATE dbo.LabStock SET Qty = Qty - @Qty
        WHERE ProductID = @ProductID AND Qty >= @Qty;
        IF @@ROWCOUNT <> 1
            THROW 50002, N'Товар отсутствует или остатка недостаточно', 1;
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
        THROW;
    END CATCH;
END;
```

Процедура начинает отдельный пакет и предполагает вызов без внешней транзакции. Уменьшение и проверка остатка объединены в одной команде, поэтому два сеанса не должны проходить через отдельную устаревшую проверку `SELECT`. Ограничение дополнительно удерживает инвариант.

**Разбор границ:** нулевое и отрицательное количество отвергаются; точный остаток превращается в ноль; неизвестный товар и нехватка дают один согласованный отказ. Если бизнес требует разные сообщения, продумайте их достоверность при конкурентном доступе.

**Проверка в будущем:** остаток 1, два подключения одновременно берут по 1; только одно должно успешно уменьшить его. Это сценарий для выполнения, не уже проведённый тест.

**Вопрос на развитие.** Как безопасно повторить вызов после сетевого обрыва, если неизвестен результат commit? Добавить уникальный идентификатор бизнес-операции и атомарную регистрацию результата; обычный retry может списать повторно. Также обсудите владение внешней транзакцией и логирование ошибки без её сокрытия.
