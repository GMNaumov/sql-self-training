# Итоговый чек-лист

Готовность проверяйте выполнением и объяснением, а не количеством знакомых слов. Сейчас доступна самостоятельная письменная проверка; практическую часть отметьте только после запуска на SQL Server 2014 Enterprise.

| Область | Что нужно суметь показать |
|---|---|
| SQL | Фильтры, NULL, joins, агрегаты, EXISTS, CTE, окна; объяснить число строк |
| Проектирование | Выбрать ключи, зерно и ограничения, объяснить нормализацию и историю |
| T-SQL | Процедура с параметрами, наборная обработка, безопасный dynamic SQL, ошибки |
| Конкуренция | Отличить blocking от deadlock, выбрать изоляцию, объяснить retry |
| Производительность | Прочитать план, сравнить оценки и факты, измерить IO/CPU, выбрать индекс |
| In-Memory | Выбрать hash/range, durability, обработать конфликты и ограничения 2014 |
| Эксплуатация | Составить backup-цепочку, объяснить restore, CHECKDB, журнал и мониторинг |
| Безопасность и HA | Минимальные права, ключи, TLS, границы AG/FCI/backup |
| DW и BI | Зерно, SCD, ETL, меры, календарь, processing, проверка отчёта |

**Пробное интервью на 60 минут:** 15 минут — последние два заказа каждого клиента; 15 — безопасное списание остатка; 15 — разбор плана с плохой оценкой; 15 — восстановление после ошибочного удаления. Уточните ничьи, пустые наборы, конкуренцию и требования к потере данных до решения.

Оцените каждую задачу: 0 — не решена, 1 — работает только на обычном случае, 2 — учитывает границы и объясняется, 3 — подтверждена осмысленными испытаниями и обсуждением альтернатив. Это личная шкала прогресса, а не гарантия найма.

**Пример честного ответа:** «Я предложил индекс и ожидаю меньшего чтения; подтвержу actual plan и STATISTICS IO на нескольких параметрах». Не называйте гипотезу измеренным фактом.

Если пробел повторяется, вернитесь к соответствующей теме и решите новый вариант без подсказки. Следующий этап проекта — отдельные SQL/T-SQL-файлы и полноценные лаборатории после отдельного запроса и подготовки экземпляра.
