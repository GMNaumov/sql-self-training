# Service Broker

Service Broker обеспечивает транзакционные сообщения в SQL Server. Message type задаёт допустимый формат, contract — разрешённые направления, queue хранит сообщения, service представляет адресуемую службу, dialog связывает участников разговора.

**Пример.** Оформление заказа в одной транзакции сохраняет заказ и отправляет сообщение о необходимости обработки. Если транзакция откатывается, нет ни заказа, ни сообщения. Обработчик позже получает сообщение через `RECEIVE`, меняет состояние и подтверждает свою транзакцию.

```sql
-- Только после настройки собственной учебной очереди:
BEGIN TRANSACTION;
WAITFOR
(
    RECEIVE TOP (1) conversation_handle, message_type_name, message_body
    FROM dbo.LabOrderQueue
), TIMEOUT 1000;
-- В настоящем обработчике здесь валидация и изменение данных.
ROLLBACK TRANSACTION;
```

`dbo.LabOrderQueue` должна быть заранее создана как очередь Broker, не как обычная таблица. Откат демонстрационно возвращает получение сообщения. Это не полный обработчик: нужно различать пользовательские сообщения, ошибки и завершение диалога, корректно закрывать разговоры и управлять повторами.

Активация (activation) может запускать процедуру обработки при поступлении. Постоянно ошибочное сообщение способно вызвать повторные откаты и отключение очереди (poison message handling). Нужны диагностика, изоляция проблемного события и восстановление обработки.

**Ошибка:** обещать ровно один внешний платёж только благодаря очереди. Транзакционные гарантии Broker не превращают внешний HTTP-вызов в часть той же локальной транзакции. Нужен устойчивый ключ операции и идемпотентность внешней стороны.
