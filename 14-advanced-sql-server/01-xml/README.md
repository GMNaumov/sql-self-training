# Работа с XML

Тип `xml` хранит корректный XML-документ или содержимое. Методы `value`, `exist`, `nodes` и `query` позволяют извлекать скаляр, проверять наличие, разворачивать узлы и получать XML-фрагмент. Для генерации XML из строк используется `FOR XML`.

```sql
DECLARE @Order xml = N'<order id="1"><item product="707" qty="2"/>
<item product="708" qty="1"/></order>';
SELECT n.i.value('(@product)[1]', 'int') AS ProductID,
       n.i.value('(@qty)[1]', 'int') AS Qty
FROM @Order.nodes('/order/item') AS n(i);
```

`nodes` создаёт по строке на `item`; `value` читает атрибут и преобразует его к `int`. `[1]` выражает ожидание единственного значения. Пример даст пары 707/2 и 708/1. Ошибка числового формата должна обрабатываться на границе приёма документа.

Типизированный XML связан с коллекцией XML Schema, нетипизированный проверяет XML-форму, но не все бизнес-правила. Пространства имён важны: путь без нужного namespace может ничего не найти в документе, хотя узел визуально существует.

**Пример применения:** получить документ поставщика, проверить и развернуть позиции в staging, затем загрузить реляционные таблицы с ключами и ограничениями. Не храните часто фильтруемый `ProductID` только внутри большого документа без оценки индексов и запросов.

**Ошибка:** собирать XML конкатенацией строк, забывая экранировать `&` и `<`. `FOR XML ... TYPE` создаёт корректное представление из данных. JSON-функций SQL Server 2016 здесь нет.
