# Сжатие данных

Сжатие данных (data compression) сокращает хранение ценой дополнительной CPU-работы. Row compression оптимизирует представление значений строки; page compression добавляет методы сжатия повторений на странице. Columnstore использует другую организацию и собственные варианты сжатия.

В SQL Server 2014 Enterprise можно оценить row/page для подходящих дисковых объектов:

```sql
EXEC sys.sp_estimate_data_compression_savings
    @schema_name = N'Sales',
    @object_name = N'SalesOrderDetail',
    @index_id = NULL,
    @partition_number = NULL,
    @data_compression = N'PAGE';
```

Выполняется в AdventureWorks2014. Это оценка, а не включение сжатия; она тоже требует ресурсов и временного места. Реальная выгода зависит от повторяемости значений и типов. Факт оценки не заменяет испытание чтения и записи.

**Пример.** Большая таблица продаж с повторяющимися датами и ключами может заметно уменьшиться и требовать меньше чтений. При CPU-насыщенной нагрузке декомпрессия и изменения могут увеличить процессорную цену. Горячие и исторические секции допускают разные решения, если модель секционирована.

Изменение сжатия обычно связано с перестроением объекта и требует планирования журнала, места, блокировок и времени. Не переносите доступность сжатия в Standard новых версий на SQL Server 2014 Standard; целевая редакция здесь Enterprise.

**Ошибка:** сообщать коэффициент экономии без измерений или сравнивать только размер файла. Проверьте занятые страницы, длительность, CPU и цену записи на одинаковом наборе.
