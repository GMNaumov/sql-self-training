# Resource Governor

Resource Governor распределяет часть ресурсов между группами нагрузки. Resource pool задаёт ресурсные границы, workload group — свойства запросов группы, classifier function определяет группу нового подключения. В SQL Server 2014 Enterprise доступны также средства управления I/O, с условиями и ограничениями версии.

**Пример.** Дневное оформление заказов и тяжёлые отчёты используют один экземпляр. Отдельные служебные логины или проверяемые признаки подключения позволяют отнести отчёты в группу и ограничить их влияние. Приложение должно иметь устойчивый признак классификации; пользовательский `APP_NAME` нельзя считать доверенной границей безопасности.

```sql
SELECT name, group_id, pool_id
FROM sys.resource_governor_workload_groups;
SELECT is_enabled FROM sys.resource_governor_configuration;
```

Это чтение состояния, а не применение политики. Создание pool, group и classifier требует продуманной процедуры, прав и проверки новых подключений. Уже существующий сеанс не начинает заново классифицироваться на каждом запросе.

Ограничения CPU, память гранта, степень параллелизма и I/O имеют разную семантику. Мягкая доля CPU при конкуренции не равна жёсткому пределу одного запроса. Resource Governor не контролирует любую память процесса и не устраняет блокировки или плохую модель запроса.

**Ошибка:** сложный classifier, обращающийся к тяжёлым или недоступным объектам, усложняет вход в систему. Функция должна быть простой и иметь безопасную группу по умолчанию.

**Самопроверка.** Ускорится ли плохой отчёт от ограничения его ресурсов? Обычно нет; задача ограничения — защитить соседей, а сам отчёт нужно оптимизировать отдельно.
