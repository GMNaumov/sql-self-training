# Пространственные данные и HierarchyID

`geometry` моделирует плоские координаты, `geography` — географические объекты на поверхности Земли. SRID определяет систему координат; сравнение объектов с несовместимыми SRID не даёт осмысленного расстояния. `hierarchyid` хранит путь узла дерева, но сам по себе не создаёт все бизнес-правила иерархии.

```sql
DECLARE @A geography = geography::Point(55.7558, 37.6173, 4326);
DECLARE @B geography = geography::Point(55.7600, 37.6200, 4326);
SELECT @A.STDistance(@B) AS DistanceMeters;

DECLARE @Node hierarchyid = hierarchyid::Parse('/1/2/');
SELECT @Node.ToString() AS NodePath,
       @Node.GetLevel() AS NodeLevel,
       @Node.GetAncestor(1).ToString() AS ParentPath;
```

В `geography::Point` сначала широта, затем долгота. Для SRID 4326 расстояние возвращается в метрах; точное численное значение здесь не измерялось. Узел `/1/2/` имеет уровень 2 и предка `/1/`.

**Пример задачи.** Найти ближайший пункт выдачи к покупателю — spatial. Хранить каталог категорий с вложенностью — hierarchyid. Для дерева нужны уникальность пути, правило создания потомков и согласованность при конкурентных вставках. Наличие `/1/2/` не гарантирует, что строка родителя реально сохранена.

**Ошибки:** менять местами широту и долготу; смешивать метры и градусы; считать пространственный индекс гарантией любого быстрого поиска; воспринимать путь как автоматически поддерживаемый внешний ключ. Сначала проверяйте модель и единицы, затем план.
