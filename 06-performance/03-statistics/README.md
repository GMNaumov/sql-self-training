# Статистика и оценка кардинальности

Статистика (statistics) описывает распределение значений. Оптимизатор оценивает число строк — кардинальность (cardinality) — и выбирает соединения, доступ и память. Статистика не является индексом, хотя создание индекса обычно создаёт связанную статистику.

```sql
SELECT s.name, s.auto_created, s.user_created
FROM sys.stats AS s
WHERE s.object_id = OBJECT_ID(N'Sales.SalesOrderHeader');
-- Затем подставьте существующее имя из результата:
-- DBCC SHOW_STATISTICS ('Sales.SalesOrderHeader', 'ИмяСтатистики');
```

Гистограмма содержит не больше 200 шагов и строится по первому столбцу статистики. Для нескольких столбцов есть сведения о плотности комбинаций, но это не многомерная подробная гистограмма всех сочетаний.

**Пример.** У большинства покупателей один заказ, у крупного — тысячи. Средняя оценка может плохо описывать крупного клиента. После массовой загрузки новых дат старая статистика также может недооценивать свежий диапазон.

В SQL Server 2014 совместимость `120` включает новый оценщик кардинальности; совместимость базы и актуальность статистики — разные факторы. Автообновление зависит от изменений и настроек, а не от обещания обновлять всё перед каждым запросом.

**Действия при ошибке оценки:** сравните estimated и actual rows, проверьте параметры, предикаты, статистику и корреляции. При обоснованной необходимости обновите конкретную статистику в лаборатории и повторите измерение. `FULLSCAN` читает все данные и может быть дорогим.

**Ошибка:** обновлять всю статистику постоянно ради любого замедления. Это создаёт нагрузку и может вызвать перекомпиляции; сначала найдите причину.
