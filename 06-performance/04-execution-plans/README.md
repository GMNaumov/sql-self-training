# Планы выполнения запросов

План выполнения (execution plan) — дерево физических операций, выбранных оптимизатором. Запрос описывает результат, план — способ его получить. Даже одинаковый SQL может получить разные планы при других индексах, статистике, параметрах или настройках.

**Пример маршрута данных:** Index Seek находит заказы покупателя, Nested Loops соединяет их с позициями, агрегат суммирует продажи. Другой план может просканировать позиции и использовать Hash Match. Оба корректны; выгодность зависит от числа строк и ресурсов.

В графическом плане SSMS обычно прослеживают потоки от источников справа к результату слева, читая связи дерева, а не только положение значков. Открывайте свойства операторов: условие поиска, остаточный фильтр, оценённые и фактические строки, число выполнений, предупреждения.

Проценты стоимости — оценки оптимизатора относительно других операторов плана. Это не проценты реально измеренного времени. Большая стрелка показывает объём потока по сведениям плана, но не объясняет автоматически источник задержки.

**Порядок анализа:** найдите расхождение числа строк, повторные чтения, сортировки и spills; сопоставьте это с `STATISTICS IO/TIME` и ожиданиями. Один красивый план без измерений не подтверждает ускорение.
