# Предупреждения планов и кэш планов

Кэш планов (plan cache) хранит скомпилированные планы для повторного использования. Это экономит CPU компиляции, но сохранённый план может плохо подходить другому параметру. Кэш не является постоянным архивом: рестарт, вытеснение и перекомпиляция меняют его содержимое.

```sql
SELECT TOP (10) qs.execution_count, qs.total_logical_reads,
       qs.total_worker_time, txt.text
FROM sys.dm_exec_query_stats AS qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) AS txt
ORDER BY qs.total_logical_reads DESC;
```

В SQL Server 2014 для общего обзора обычно нужно `VIEW SERVER STATE`. Значения накоплены за жизнь записи, поэтому большой total может означать частые дешёвые вызовы. Сравнивайте среднее, частоту и вклад в общую нагрузку; статистика не охватывает всю историю сервера.

Предупреждения плана могут указывать spill сортировки или хеша, преобразование типов, мешающее оценке или поиску, и отсутствие полезного индекса. Отсутствие значка предупреждения не доказывает отсутствие проблемы.

**Пример.** Столбец хранит `varchar`, а параметр передан как `nvarchar`; преобразование на стороне столбца иногда ухудшает доступ и оценку. Проверяйте точные типы, длины и сопоставления, а не только текст `WHERE`.

**Ошибка:** выполнять глобальный `DBCC FREEPROCCACHE` как лечение. Это обнуляет накопленную пользу компиляции для других запросов. В лаборатории исследуйте конкретный модуль и причину. Query Store в 2014 отсутствует; постоянную историю нужно собирать отдельно.
