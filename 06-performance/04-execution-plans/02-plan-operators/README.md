# Операторы планов выполнения

Физический оператор выполняет конкретный шаг. Seek выбирает диапазон по индексу, Scan просматривает источник, Filter отбрасывает строки, Sort упорядочивает, Aggregate считает группы. Key Lookup добирает столбцы из кластерного индекса.

| Соединение | Когда часто полезно | Что проверить |
|---|---|---|
| Nested Loops | Небольшой внешний набор и быстрый поиск внутри | Число повторных обращений |
| Hash Match | Большие несортированные наборы | Память и spill |
| Merge Join | Подходящие отсортированные входы | Цена сортировок, повторы ключей |

**Пример.** Для пяти заказов Nested Loops с поиском позиций может быть выгоден. Для половины заказов повторный поиск миллионов позиций может уступить сканированию и хеш-соединению. Выбор оператора оценивайте вместе с реальными строками, а не по любимому значку.

Seek также может прочитать широкий диапазон и отфильтровать почти всё остаточным предикатом. Смотрите Seek Predicates и Predicate отдельно. Scan небольшого покрывающего индекса может быть вполне оптимальным.

Spool сохраняет промежуточные данные для повторного использования или защиты корректности изменения. Его присутствие не всегда ошибка. Параллельный план включает обмены потоками; при малом объёме накладные расходы параллелизма могут перевесить пользу.

**Самопроверка.** Нужно ли принудительно заменить Hash Match на Nested Loops ради ускорения? Сначала проверьте оценки, индексы и входные объёмы. Hint фиксирует частное решение и может ухудшить другую ситуацию.
