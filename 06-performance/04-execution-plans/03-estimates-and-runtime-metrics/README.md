# Оценки строк и фактические показатели

Estimated rows — ожидание при компиляции, actual rows — наблюдение при выполнении. Сильное расхождение часто объясняет неудачный алгоритм соединения или размер выделенной памяти. При повторно выполняемом внутреннем операторе учитывайте и число выполнений: сравнение одной цифры без её смысла вводит в заблуждение.

**Пример.** План ожидал 10 заказов покупателя, получил 10 000 и выполнил тысячи Key Lookup. Итоговые строки могут быть правильными, но чтений намного больше ожидаемого. Это повод проверить распределение покупателей и параметры компиляции.

`SET STATISTICS IO ON` показывает логические и физические чтения по объектам; `TIME` — CPU и elapsed time. Логические чтения не обнуляются от наличия данных в кеше. Длительность включает ожидания, а CPU отражает процессорную работу. В параллельном запросе суммарное CPU может превышать elapsed.

Составьте таблицу замеров: параметр, возвращённые строки, logical reads, CPU, elapsed, форма плана. Повторите на нескольких характерных параметрах, удерживая одинаковую семантику результата. Первый запуск может включать компиляцию и холодные чтения; не сравнивайте его бездумно со вторым.

**Ошибка:** принять ускорение за улучшение, если новый запрос перестал возвращать часть строк. Сначала сверяйте корректность, затем ресурсы. Нельзя честно приводить миллисекунды или число чтений из этого проекта как измеренные: SQL Server здесь не запущен.
