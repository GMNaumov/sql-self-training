# TempDB и промежуточные результаты

`tempdb` — общая системная база для временных таблиц, части промежуточных операций и версий дисковых строк. Она пересоздаётся при старте службы, поэтому не является постоянным местом хранения приложения.

Сортировки и хеш-операции запрашивают память (memory grant). Если нужные данные не помещаются, часть работы выгружается в `tempdb`: spill. Причиной может быть недооценка строк, широкие строки, большой набор или конкуренция за память.

**Пример.** Отчёт сортирует все позиции продаж со всеми столбцами ради вывода первых 20 строк. Оценка занижена, сортировка пишет промежуточные данные. Сначала ограничьте столбцы, проверьте условия и оценку, рассмотрите индекс под нужную сортировку; только затем обсуждайте увеличение ресурсов.

```sql
USE tempdb;
SELECT name, size * 8.0 / 1024 AS SizeMB,
       growth, is_percent_growth
FROM sys.database_files;
```

Размер `size` указан в страницах по 8 КБ. `growth` интерпретируется как страницы либо проценты в зависимости от `is_percent_growth`.

Различайте нехватку места, задержки диска и конкуренцию за страницы размещения. Ожидания `PAGELATCH` не означают автоматически медленный диск; `PAGEIOLATCH` связано с ожиданием ввода страниц. Настройку числа файлов, их равного размера и приращений выбирают по измерениям. Не применяйте бездумно правило «по файлу на каждое ядро».

**Самопроверка.** Удалит ли добавление файлов `tempdb` плохую оценку строк? Нет: оно решает другую причину нагрузки. В 2014 нет автоматической memory grant feedback.
