# Индексы и производительность запросов

Производительность — способность выполнить нужную работу за приемлемое время и с приемлемыми ресурсами. Время запроса складывается из вычислений, чтений, ожиданий и передачи результата. Индекс может ускорить чтение, но делает запись дороже и занимает место.

**Сквозной пример.** Поиск заказов одного покупателя может читать всю таблицу или небольшой диапазон индекса по `CustomerID`. Если покупатель имеет половину заказов, широкий scan иногда дешевле множества точечных обращений. Поэтому правило «seek хорошо, scan плохо» неверно без объёма работы.

Начните с архитектуры индексов и статистики, затем читайте планы и измеряйте показатели. Меняйте одну причину за раз. Сохраняйте текст запроса, параметры, объём данных, план, логические чтения, CPU и длительность до и после.

В SQL Server 2014 при совместимости `120` действует новый для этой версии оценщик кардинальности. Query Store, адаптивных соединений, автоматической обратной связи по памяти и пакетного режима на обычном rowstore из поздних версий здесь нет. Для истории используйте собственные замеры, DMV и Extended Events. Не очищайте общий кэш ради демонстрации: это меняет работу всех сеансов.
