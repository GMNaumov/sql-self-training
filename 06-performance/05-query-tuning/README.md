# Системная настройка запросов

Настройка запроса (query tuning) начинается с бизнес-условия и измеряемой проблемы. «Медленно» уточните: какой запрос, с какими параметрами, сколько строк, при какой параллельной нагрузке и какое допустимое время.

**Разбор.** Отчёт ищет заказы января через `YEAR(OrderDate)=2014 AND MONTH(OrderDate)=1`. Перепишите диапазоном `OrderDate >= '20140101' AND OrderDate < '20140201'`. Затем сравните план и чтения с подходящим индексом. Диапазон лучше выражает границы, но сам по себе не гарантирует seek: запрос может выбирать большую часть таблицы.

Рабочая последовательность:

1. Подтвердите правильность и сохраните исходный результат на стабильных данных.
2. Измерьте чтения, CPU, длительность, план и ожидания.
3. Найдите основной расход: лишние строки, повторные обращения, неверная оценка, сортировка, ожидание.
4. Измените один фактор: предикат, индекс, статистику или форму запроса.
5. Сравните несколько характерных параметров и цену изменений данных.

Сокращение выбранных столбцов может уменьшить сеть, чтения и память. Предварительная агрегация помогает избежать размножения строк. При этом CTE вместо подзапроса не гарантирует ускорения: синтаксическая красота и физическая работа — разные свойства.

**Ошибка:** вводить hint раньше диагностики. Принудительный индекс или алгоритм может помочь одному параметру и повредить другому. Документируйте причину и условия пересмотра такого решения.

**Самопроверка.** Запрос ускорился в десять раз после запуска соседа. Доказано ли улучшение? Нет: изменились кеш, нагрузка или блокировки. Нужны сопоставимые условия.
