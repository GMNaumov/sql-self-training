# Архитектура индексов

Дисковые индексы строкового хранения (rowstore) организованы как B+-деревья. Корень и промежуточные уровни направляют поиск, листья содержат данные индекса. Страница SQL Server обычно имеет размер 8 КБ. Логическое чтение — обращение к странице в буферном кеше; оно остаётся работой, даже без физического чтения диска.

Кластеризованный индекс (clustered index) хранит строки таблицы на листовом уровне в логическом порядке ключа. Он один на таблицу. Таблица без него — куча (heap). Некластеризованный индекс хранит собственные ключи и указатель на строку: кластерный ключ либо RID для кучи.

```sql
SELECT i.name, i.type_desc, i.is_unique
FROM sys.indexes AS i
WHERE i.object_id = OBJECT_ID(N'Sales.SalesOrderHeader');
```

Запрос показывает существующие индексы, а не предлагает создавать новые. Первичный ключ — правило целостности; кластеризованный индекс — способ организации хранения. Часто они совпадают, но это не обязательное условие.

**Пример.** Некластерный индекс по `CustomerID` находит ключи заказов. Если запросу нужен столбец вне индекса, движок может выполнить Key Lookup в кластерное дерево. Для пары строк это дёшево, для тысяч — дорого.

**Ошибки:** ожидать сортировку результата без `ORDER BY`; выбирать широкий изменяемый кластерный ключ без оценки его присутствия в некластерных индексах; считать фрагментацию единственной причиной медленного запроса. Сначала измеряйте чтения и фактический объём.
