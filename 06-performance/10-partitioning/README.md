# Секционирование таблиц и индексов

Секционирование (partitioning) делит одну логическую таблицу или индекс на части по функции ключа. Функция задаёт границы, схема секционирования связывает части с файловыми группами. Приложение по-прежнему обращается к одной таблице.

**Пример.** Продажи разделены по месяцу `OrderDate`. Запрос диапазона за январь может прочитать только январскую секцию — partition elimination. Без подходящего условия движок всё равно затронет многие части. Индексный поиск и устранение секций — разные механизмы.

Для будущей отдельной базы описание границы выглядит так:

```sql
CREATE PARTITION FUNCTION pf_LabSalesDate(date)
AS RANGE RIGHT FOR VALUES ('20140201', '20140301');
```

`RANGE RIGHT` относит границу к правой секции: первая содержит даты до 1 февраля, вторая — февраль, третья — начиная с 1 марта. Для реальной таблицы дополнительно нужны partition scheme и размещение по ней. Одной функции недостаточно.

Главная польза часто эксплуатационная: переключить подготовленную секцию через `ALTER TABLE ... SWITCH`, отдельно обслуживать или архивировать. SWITCH требует совместимых структур, индексов, ограничений и правильных границ; это не произвольное перемещение строк.

Уникальный выровненный индекс обычно должен включать ключ секционирования, что влияет на модель ключей. В SQL Server 2014 Enterprise функциональность доступна, но решение требует оценки сопровождения.

**Ошибка:** секционировать маленькую таблицу ради ускорения. Само число частей не уменьшает объём нужных данных и может усложнить план и обслуживание.
